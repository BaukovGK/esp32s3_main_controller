## 1. Топология шины RS-485

```
  ESP32-S3 (master) ── UART/RS-485 (RE/DE)
        │
        ├── slave 1   Waveshare Analog Input 8CH       (4–20 мА × 8)
        ├── slave 2   УРЖ2КМ (расходомер ультразвук.)  (двухканальный)
        ├── slave 10  СЛ21-100Т «концентрат/пермеат-2» (2 ячейки + 2 t°)
        ├── slave 11  СЛ21-100Т «питание/пермеат-1»    (2 ячейки + 2 t°)
        ├── slave 20  KWS-308L «насос НД»              (TBD)
        └── slave 21  KWS-308L «насос ВД»              (TBD)
```

> Адреса 10/11 и 20/21 — рекомендация (выбраны вне «1..9»-зоны общих заводских default'ов, чтобы не конфликтовать).
> УРЖ2КМ из коробки идёт addr=001, поменяйте на 2 через меню или ModBus Universal до подключения к шине.
> Waveshare AI 8CH из коробки addr=1, baud=9600 — оставляем как есть.

### Общие параметры

| Параметр | Значение | Откуда |
|---|---|---|
| Скорость | **9600 8N1** | максимум что выдержат все 4 типа устройств одновременно (СЛ21 умеет 19200, остальные — 9600 default) |
| Чётность | None | СЛ21 поддерживает Even/Odd/Stop2 — переключить на None через меню |
| Стоп-биты | 1 | |
| Inter-frame | ≥3.5 char (~4 мс на 9600) | стандарт Modbus RTU |
| Период опроса | см. таблицу ниже | разные slave — разные периоды |

| Slave | Устройство | Период | Тип данных | CID в коде |

## 2. СЛ21-100Т (анализатор удельной электропроводности)

**Источник:** `doc/sl21.pdf`, раздел 5.16 (МВ интерфейс).

### 2.1 Параметры связи

| Параметр | Default | Допустимо |
|---|---|---|
| Slave address | **5** | 1..247 |
| Baud rate | 19200 | 9600 / 19200 |
| Parity | Even | Even / Odd / Stop2 |
| Function code | **0x03 (Read Holding Registers)** только |

### 2.2 Карта регистров (одно устройство = 2 ячейки X1/X2 + 2 термодатчика t1/t2)

| Адрес (Modicon) | Адрес (zero-based) | Имя | Тип | Формула → физ. ед. |
|---:|---:|---|---|---|
| 40001 | 0x0000 | Х1 LO  | uint16 (мл. слово) | см. §2.3 |
| 40002 | 0x0001 | Х1 HI  | uint16 (ст. слово) | (HI<<16 \| LO) / divisor |
| 40003 | 0x0002 | t1     | int16 | `t°C = raw / 10` |
| 40004 | 0x0003 | Х2 LO  | uint16 | см. §2.3 |
| 40005 | 0x0004 | Х2 HI  | uint16 | (HI<<16 \| LO) / divisor |
| 40006 | 0x0005 | t2     | int16 | `t°C = raw / 10` |

> ⚠️ **Word-order:** младшее слово в МЛАДШЕМ регистре (40001 = LO). Это противоположно дефолту ESP-IDF mbc_master, который для 32-битных типов ждёт «hi first». Поэтому в драйвере `conductivity.c` мы читаем 6 регистров как `uint16_t[6]` и собираем 32-битное значение вручную: `value = ((uint32_t)reg[1] << 16) | reg[0]`.

### 2.3 Формат электропроводности

| Модель | Формула | Дивизор |
|---|---|---:|
| СЛ21-1Т | `XXXX.XXXX мкСм/см × 10000` | 10000 |
| СЛ21-10Т | `XXXXX.XXX мкСм/см × 1000` | 1000 |
| **СЛ21-100Т** ⬅︎ наш случай (×2) | `XXXXXX.XX мкСм/см × 100` | **100** |

> В коде сейчас `SL21_COND_DIVISOR = 100` (см. `components/drivers/conductivity.c`). Это правильно для СЛ21-100Т.

### 2.4 Сценарий «один блок = 2 канала»

⚠️ **Важно для текущей реализации:** один блок СЛ21 имеет ДВЕ независимые ячейки проводимости (X1, X2) и ДВА термодатчика (t1, t2). То есть **два блока СЛ21-100Т → 4 канала проводимости + 4 канала температуры**.

Текущая реализация (`modbus_poller.c`):
```c
CID_COND_ADDR10  → 6 регистров (полный блок: X1+X2+t1+t2) ← OK
CID_COND_ADDR11  → 3 регистра (только X1+t1) ← НЕПОЛНО
```

**Рекомендация:** оба слейва опрашивать как 6 регистров, использовать оба канала. Это даёт 4 точки проводимости вместо 3, что соответствует физике установки:
- блок 11 X1 = вход (питательная вода)
- блок 11 X2 = пермеат 1 ступени
- блок 10 X1 = пермеат 2 ступени (товарный)
- блок 10 X2 = концентрат

### 2.5 Терминатор и подключение

В каждом блоке есть джампер 120 Ом (Приложение 3). Замкнуть только на ОДНОМ конце линии (на ESP32-S3 уже есть терминатор).

## 3. УРЖ2КМ (ультразвуковой расходомер двухканальный)

**Источник:** `doc/re_urg2kmm2.pdf` (Руководство ТЕСС 421457.015 РЭ).

> ⚠️ **Полной карты регистров Modbus в этом PDF НЕТ** — производитель ссылается на отдельный документ «Описание протокола размещено на сайте предприятия-изготовителя» (стр. 24 PDF, п. 2.2.8.5.1). Действующая карта в коде получена из текущей реализации `components/drivers/flowmeter.c` и должна быть **сверена с протоколом ModBus Universal** перед окончательным релизом. Адреса ниже — наблюдаемые, не нормативные.

### 3.1 Параметры связи

| Параметр | Default | Допустимо |
|---|---|---|
| Slave address | **001** | 1..247 (в коде используем 2) |
| Baud rate | программируется (1.2 / 2.4 / 4.8 / 9.6 / 14.4 / 19.2 КБод) | используем **9600** |
| Тип протокола | RTU / ASCII | **RTU** |
| Function code | 0x03 (Read Holding) — основной | |
| Каналы измерения | **2** (F1, F2) | один блок = две трубы ⇒ для 4 точек учёта нужно 2 блока УРЖ2КМ |

### 3.2 Уточнение пользователя «4 расходомера»

УРЖ2КМ — **двухканальный** прибор. «4 расходомера» — это либо:
- **4 канала** (вариант, на который рассчитана текущая реализация: 8 регистров расхода / 2 = 4 float). Тогда нужно **2 прибора УРЖ2КМ** на одной шине, slave 2 и slave 3.
- **4 ПЭП-преобразователя** на 2 канала (по 2 пары ПЭП на канал) — это физика одного двухканального прибора, не 4 точки расхода.

**Действие:** уточнить у заказчика. Сейчас код опрашивает один slave=2 и берёт 4 float расхода + 8 float объёма с холдингов 0x0000 и 0x0036, что соответствует **двум блокам УРЖ2КМ**, объединённым в один shared addr (нестандартно), либо ошибочной адресации.

### 3.3 Формат данных — word-swapped IEEE 754 float

УРЖ2КМ хранит float в **двух последовательных регистрах с обратным порядком слов**:

```
addr+0  → младшее слово (mantissa low)
addr+1  → старшее слово (sign + exponent + mantissa hi)
```

Внутри слова — big-endian (стандарт Modbus). Сборка:
```c
uint32_t ieee = ((uint32_t)reg_hi << 16) | (uint32_t)reg_lo;
float result;
memcpy(&result, &ieee, sizeof(float));
```
(см. `flowmeter.c::urzh_regs_to_float`).

### 3.4 Карта регистров (наблюдаемая в текущей реализации)

| Holding | Имя | Тип | Канал | Ед. изм. | Источник |
|---:|---|---|---|---|---|
| 0x0000–0x0001 | F1 (расход 1 канал) | float-WS | 1 | м³/ч | `CID_FLOW_RATES`, off 0–1 |
| 0x0002–0x0003 | F2 (расход 2 канал) | float-WS | 2 | м³/ч | off 2–3 |
| 0x0004–0x0005 | F3 ⚠️ | float-WS | 3? | м³/ч | off 4–5 (TBD) |
| 0x0006–0x0007 | F4 ⚠️ | float-WS | 4? | м³/ч | off 6–7 (TBD) |
| 0x0036–0x0037 | V1 (объём 1 канал) | float-WS | 1 | м³ | `CID_FLOW_VOLUMES`, off 0–1 |
| 0x0038–0x0039 | V2 | float-WS | 2 | м³ | off 2–3 |
| 0x003A–0x003B | V3 ⚠️ | float-WS | 3? | м³ | off 4–5 |
| 0x003C–0x003D | V4 ⚠️ | float-WS | 4? | м³ | off 6–7 |
| 0x003E–0x003F | V5 ⚠️ | float-WS | 5? | м³ | off 8–9 |
| 0x0040–0x0041 | V6 ⚠️ | float-WS | 6? | м³ | off 10–11 |
| 0x0042–0x0043 | V7 ⚠️ | float-WS | 7? | м³ | off 12–13 |
| 0x0044–0x0045 | V8 ⚠️ | float-WS | 8? | м³ | off 14–15 |

⚠️ **Расход**: в реальности УРЖ2КМ-Модель 2 двухканальный (по PDF, п. 1.1.2). Адреса 0x0004–0x0007 в текущей реализации могут возвращать F1/F2 в иных единицах (л/мин? «грубое» значение?), а не F3/F4. **Сверить с протоколом ModBus Universal.**
⚠️ **Объём**: 16 регистров = 8 float — слишком много для двухканального прибора. Возможно, это V1/V2 + накопленные за разные периоды (час/сутки/месяц), либо T1/T2 (наработка), либо «состояние НОРМА/ОТКАЗ». PDF на стр. 23 упоминает: «F1, F2 — мгновенные расходы, V1, V2 — накопленные объёмы, T1, T2 — время наработки, o1, o2 — состояние НОРМА/ОТКАЗ». Это **6 параметров × 2 канала = 12 значений**. 8 float покрывают 4 параметра × 2 канала. Лучше разбить чтение на отдельные блоки и явно мапить.

## 4. Waveshare Modbus RTU Analog Input 8CH

**Источник:** https://www.waveshare.com/wiki/Modbus_RTU_Analog_Input_8CH (кэш в `doc/ws_ai.html`), раздел «Development Protocol V2».

### 4.1 Параметры связи

| Параметр | Default |
|---|---|
| Slave address | **1** |
| Baud rate | **9600** |
| Parity | None |
| Stop bits | 1 |
| Function codes | 0x03 / 0x04 / 0x06 / 0x10 |

### 4.2 Полная карта регистров (Development Protocol V2)

| Адрес (HEX) | Имя | Тип | R/W | FC |
|---:|---|---|---|---|
| **3x0000…3x0007** | Каналы 1..8 — мгновенные значения | uint16 BE | R | **0x04** |
| 4x1000…4x1007 | Каналы 1..8 — режим (mode 0..4) | uint16 | RW | 0x03 / 0x06 / 0x10 |
| 4x2000 | UART params (HI=parity, LO=baud) | uint16 | RW | 0x03 / 0x06 |
| 4x4000 | Device address (1..255) | uint16 | RW | 0x03 / 0x06 |
| 4x8000 | Software version (BCD/100) | uint16 | R | 0x03 |

> «3x» = Input Register (FC 0x04), «4x» = Holding Register (FC 0x03/0x06/0x10).

### 4.3 Режимы каналов (регистр 4x1000+ch)

| Mode | Версия (A) | Версия (B) | Сырое значение что значит |
|---:|---|---|---|
| 0 | 0–5 V | 0–10 V | напряжение |
| 1 | 1–5 V | 2–10 V | напряжение |
| 2 | 0–20 mA | 0–20 mA | ток |
| 3 | **4–20 mA** | 4–20 mA | ток |
| 4 | 4096-scale | 4096-scale | сырое АЦП (0..4095) |

### 4.4 Формула преобразования

**В режимах 2/3 (mA) сырое значение возвращается напрямую в µA**:
```c
float current_mA = (float)raw_uint16 / 1000.0f;   // 20.000 mA = 20000 µA
```
**В режимах 0/1 (V) — в mV**:
```c
float voltage_V = (float)raw_uint16 / 1000.0f;    // 10.000 V = 10000 mV
```
**В режиме 4 (scale code) — линейно через формулы:**
```c
float V = scale * 3300.0f / 4095.0f / op_amp_ratio;  // op_amp_ratio = 32.4/49.9 для A
float I_A = V / R_sense;                              // R_sense = 249 Ω для A
```

⚠️ **Пробел в текущей реализации `analog_input.c`:** код использует
```c
float ratio = (float)avg / ADC_RAW_MAX;  // ADC_RAW_MAX = 4095
```
— это работает только если канал переведён в режим **4 (scale code)**, и даёт **только относительное значение 0..1**, но НЕ корректные мА. Для правильной работы:
- либо настроить все 8 каналов в **mode 3 (4–20 mA)** через регистры 4x1000..4x1007 и читать `raw / 1000.0f` как мА → `(mA - 4) / 16 * (range_max - range_min) + range_min`;
- либо оставить mode 4, но применить формулу через op_amp_ratio + R_sense.

Рекомендация: при инициализации (один раз) записать `4x1000..4x1007 = 0x0003` (mode = 4–20 mA), затем в драйвере конвертить `raw_uA → mA → physical`.

### 4.5 Адресация каналов

Channel 1 → 0x0000 (input), 0x1000 (config)
Channel 2 → 0x0001, 0x1001
... последовательно до Channel 8 → 0x0007, 0x1007.

В текущем коде `s_ai_data[ch]` — индекс 0..7 совпадает с каналом 1..8 после смещения, всё ок.

### 4.6 Команды записи (для one-time setup)

```
# Перевести канал 1 в 4-20 mA (mode 3)
01 06 10 00 00 03 [CRC]

# Перевести все 8 каналов в 4-20 mA (mode 3) одним фреймом
01 10 10 00 00 08 10 00 03 00 03 00 03 00 03 00 03 00 03 00 03 00 03 [CRC]

# Прочитать раз 8 каналов
01 04 00 00 00 08 F1 CC

# Сменить slave address на 2
01 06 40 00 00 02 [CRC]

# Прочитать версию ПО (раз для верификации)
01 03 80 00 00 01 [CRC]
```

⚠️ Уточнить: **KWS-308L** — это **1-фазный** счётчик. Для 3-фазного ВД-насоса подойдёт KWS-308PR3 / DTS634 / аналог. **Уточнить у заказчика.**

### 5.4 Алгоритм диагностики (после получения datasheet)

```c
typedef enum {
    CID_KWS_PUMP_LP = ...,   // slave 20
    CID_KWS_PUMP_HP = ...,   // slave 21
} kws_cid_t;

typedef struct {
    float voltage_V;
    float current_A;
    float power_W;
    float energy_kWh;
    float frequency_Hz;
    float power_factor;
    uint16_t alarm_flags;
    bool valid;
} kws_data_t;
```

Алярмы:
- `voltage_V < 200` или `> 250` → 1-фаза out-of-range → ALARM
- `current_A == 0` при состоянии SM = AUTO_RUNNING → насос не запустился (дублирует контроль через 4-20мА давление, но ловит обрыв обмотки)
- `power_factor < 0.5` → проблема с пуском двигателя

## 6. Сводная карта сигналов установки → устройство → регистр

### 6.1 Аналоговые входы 4–20 мА (через Waveshare AI 8CH, slave 1)

| Канал AI | Сигнал | Диапазон | Регистр | Ед. изм. |
|---:|---|---|---:|---|
| 1 | Давление **до НД-насоса** (P1) | 0–10 бар | `IN 0x0000` | бар |

## 8. Открытые вопросы (для согласования с заказчиком/наладчиком)

1. **«4 расходомера»** — это **2× УРЖ2КМ × 2 канала** или **1× УРЖ2КМ-4 канала** (если такая модификация существует)?
2. **KWS-308L** — это **однофазный** счётчик. Для **3-фазного ВД-насоса** нужно другой прибор (KWS-308PR3 / DTS634 / SDM630)?
3. **Карта точек учёта проводимости** — какая ячейка СЛ21 (#10 X1, #10 X2, #11 X1, #11 X2) приварена к какой точке (питание / пермеат 1ст / пермеат 2ст / концентрат)?
4. **Карта точек давления P1..P4** — соответствует ли §6.1 реальному монтажу?
5. **Где взять датшит KWS-308L?** Запросить у поставщика (по AliExpress order) или прислать фото LCD при разных нагрузках для реверс-инжиниринга.
6. **Скорость шины** — 9600 или 19200? Если 19200, проверить что Waveshare AI 8CH её поддерживает (по доке: HI=parity, LO=baud в 4x2000, LO=0..7 — нужны точные коды).
7. **Дозатор биоцида/реагента** — управляется через DO (релейный выход на ВД-насос вкл.), или нужен отдельный аналоговый канал? Связано с TODO в README про дозатор-в-WASHING.

## 9. Рекомендуемый план интеграции

1. **Этап 1 — настройка устройств на стенде** (без подключения к шине прошивки):
   - УРЖ2КМ #1 → addr 2, baud 9600, RTU
   - УРЖ2КМ #2 → addr 3, baud 9600, RTU (если «4 расходомера» = 2 прибора)
   - СЛ21-100Т #1 → addr 11, baud 9600, parity None
   - СЛ21-100Т #2 → addr 10, baud 9600, parity None
   - Waveshare AI 8CH → addr 1, baud 9600 (default), все 8 каналов в mode 3 (4–20 mA) через `0x10` команду
   - KWS-308L #1, #2 → addr 20, 21, baud 9600

2. **Этап 2 — реверс/верификация** карты УРЖ2КМ через `ModBus Universal` + KWS через `ModScan`. Зафиксировать реальные адреса в этом документе.

3. **Этап 3 — добавление CID в коде**:
   - `CID_FLOW2_RATES`, `CID_FLOW2_VOLUMES` (если 2 прибора УРЖ2КМ)
   - `CID_KWS_PUMP_LP`, `CID_KWS_PUMP_HP`
   - расширение `CID_COND_ADDR11` с 3 на 6 регистров

4. **Этап 4 — драйверы**: новый `components/drivers/power_meter.c` (KWS), расширение `conductivity.c` на 4 канала, исправление формулы в `analog_input.c`.

5. **Этап 5 — интеграция в `interlocks.c`** (новые INTERLOCK_PUMP_NO_CURRENT, INTERLOCK_3PH_LOSS) и в `state_machine.c` (учёт энергии в WASHING).

6. **Этап 6 — телеметрия** (`mqtt_publish.c`, `web_api_status.c`): новые поля JSON для kWh/V/A/PF, расширенная карта проводимости.
