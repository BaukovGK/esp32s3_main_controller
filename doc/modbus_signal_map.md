## 1. Топология шины RS-485

```
  ESP32-S3 (master) ── UART1/RS-485 (RE/DE)
        │
        ├── slave 1   Waveshare PWM Input 8CH       (8× freq+duty — PWM-датчики)
        ├── slave 2   УРЖ2КМ 4-канальный            (расход + объём × 4 канала)
        ├── slave 10  СЛ21-100Т #1                  (X1+X2 проводимость + t1+t2)
        ├── slave 11  СЛ21-100Т #2                  (X1+X2 проводимость + t1+t2)
        ├── slave 20  KWS-306L 3-фазный (НД-насос)  (V/I/P/E/T + реле)
        └── slave 21  KWS-306L 3-фазный (ВД-насос)  (V/I/P/E/T + реле)
```

| Параметр шины | Значение |
|---|---|
| Скорость | 9600 бод |
| Формат | 8N1 |
| Function codes используемые | 0x03 (read holding), 0x04 (read input), 0x06 (write single), 0x10 (write multiple) |

> Полная инструкция по смене адресов и параметров связи каждого устройства — в [`modbus_addresses.md`](modbus_addresses.md).

## 2. СЛ21-100Т (анализатор удельной электропроводности) — 2 шт.

**Источник:** `doc/sl21.pdf`, раздел 5.16 «МВ интерфейс».

### 2.1 Параметры

| Параметр | Значение в РЭ |
|---|---|
| Function code | **0x03 (Read Holding Registers)** только чтение |
| Default slave | 5 |
| Назначено | **10 и 11** (см. `modbus_addresses.md`) |
| Каналов на блок | **2 ячейки проводимости (X1, X2) + 2 термодатчика (t1, t2)** |

### 2.2 Карта регистров одного блока

| Holding (zero-based) | Holding (Modicon) | Имя | Тип | Восстановление физ. величины |
|---:|---:|---|---|---|
| 0x0000 | 40001 | X1 LO | uint16 | `cond_uS = ((HI<<16) \| LO) / 100`<br/>(СЛ21-**100Т**, формат `XXXXXX.XX × 100`) |
| 0x0001 | 40002 | X1 HI | uint16 | (HI вместе с LO выше) |
| 0x0002 | 40003 | t1    | int16  | `t°C = raw / 10` |
| 0x0003 | 40004 | X2 LO | uint16 | `cond_uS = ((HI<<16) \| LO) / 100` |
| 0x0004 | 40005 | X2 HI | uint16 | (HI вместе с LO выше) |
| 0x0005 | 40006 | t2    | int16  | `t°C = raw / 10` |

> ⚠️ **Word-order:** младшее слово в МЛАДШЕМ адресе (40001 = LO, 40002 = HI). Это **противоположно** дефолтному поведению ESP-IDF mbc_master. Поэтому в `conductivity.c` мы читаем 6 регистров как `uint16[6]` и собираем 32-битное значение вручную:
> ```c
> uint32_t raw = ((uint32_t)reg[1] << 16) | reg[0];
> float cond_uS = (float)raw / 100.0f;
> ```

### 2.3 Делитель в зависимости от модификации СЛ21

| Модель | Формула индикатора | Дивизор кода |
|---|---|---:|
| СЛ21-1Т | `XXXX.XXXX мкСм/см × 10000` | 10000 |
| СЛ21-10Т | `XXXXX.XXX мкСм/см × 1000` | 1000 |
| **СЛ21-100Т** ← **наш случай** | `XXXXXX.XX мкСм/см × 100` | **100** |

В коде: `SL21_COND_DIVISOR = 100` в `components/drivers/conductivity.c`. ✅

### 2.4 Логические каналы — 4 точки контроля проводимости

Один блок СЛ21 = 2 ячейки. Два блока = **4 канала проводимости + 4 канала температуры**.

| Логический канал | Slave | Регистр | Точка измерения |
|---:|---:|---|---|
| `COND_CH_FEED` | 11 | X1 + t1 | питательная вода (вход насоса НД) |
| `COND_CH_PERM1` | 11 | X2 + t2 | пермеат 1-й ступени |
| `COND_CH_PERM2` | 10 | X1 + t1 | пермеат 2-й ступени (товарный) |
| `COND_CH_CONC` | 10 | X2 + t2 | концентрат (после мембран) |

> **Текущая реализация:** в `modbus_poller.c` slave 11 опрашивает только 3 регистра (X1+t1) — нужно расширить до 6, чтобы получить 4-й канал. См. §7.

## 3. УРЖ2КМ (4-канальный ультразвуковой расходомер) — 1 шт.

**Источник:** `doc/re_urg2kmm2.pdf` + наблюдаемая семантика из `components/drivers/flowmeter.c`.

> ⚠️ **Полной нормативной карты регистров в РЭ нет** — производитель ссылается на отдельный документ «ModBus Universal» на сайте ТЕСС (п. 2.2.8.5.1 РЭ). Адреса ниже — наблюдаемые в существующей реализации, **должны быть верифицированы** на стенде через ModBus Universal.

### 3.1 Параметры

| Параметр | Значение |
|---|---|
| Тип прибора | УРЖ2КМ, **4-канальный модификация** (подтверждено заказчиком) |
| Function code | 0x03 (Read Holding) — основной |
| Default slave | 1 |
| Назначено | **2** |
| Скорость обмена | программируется: 1.2 / 2.4 / 4.8 / 9.6 / 14.4 / 19.2 КБод; **используем 9600** |
| Тип протокола | RTU / ASCII; **используем RTU** |

### 3.2 Формат данных — word-swapped IEEE 754 float

Каждый канал расхода и каждый канал объёма передаётся как **2 регистра**:
```
addr+0  → младшее слово (mantissa low)        ← LO
addr+1  → старшее слово (sign+exponent+mantissa hi)  ← HI
```
Внутри регистра — стандартный Modbus big-endian (байт hi → byte lo). Сборка float:
```c
uint32_t ieee = ((uint32_t)reg_hi << 16) | (uint32_t)reg_lo;
float result;
memcpy(&result, &ieee, sizeof(float));
```
(см. `flowmeter.c::urzh_regs_to_float`).

### 3.3 Карта регистров (4 канала)

| Holding | Имя | Тип | Канал | Ед. изм. |
|---:|---|---|---:|---|
| 0x0000–0x0001 | F1 (расход 1 канал) | float-WS | 1 | м³/ч |
| 0x0002–0x0003 | F2 (расход 2 канал) | float-WS | 2 | м³/ч |
| 0x0004–0x0005 | F3 (расход 3 канал) | float-WS | 3 | м³/ч |
| 0x0006–0x0007 | F4 (расход 4 канал) | float-WS | 4 | м³/ч |
| 0x0036–0x0037 | V1 (объём 1 канал) | float-WS | 1 | м³ |
| 0x0038–0x0039 | V2 | float-WS | 2 | м³ |
| 0x003A–0x003B | V3 | float-WS | 3 | м³ |
| 0x003C–0x003D | V4 | float-WS | 4 | м³ |
| 0x003E–0x003F | V5 ⚠️ | float-WS | (?) | (?) |
| 0x0040–0x0041 | V6 ⚠️ | float-WS | (?) | (?) |
| 0x0042–0x0043 | V7 ⚠️ | float-WS | (?) | (?) |
| 0x0044–0x0045 | V8 ⚠️ | float-WS | (?) | (?) |

⚠️ **Регистры 0x003E..0x0045** — текущий код читает 16 регистров объёма (8 float), но физических каналов всего 4. Возможные интерпретации:
- V1..V4 = текущие накопленные объёмы по 4 каналам
- V5..V8 = объёмы за предыдущий период (час/сутки), либо T1..T4 (время наработки), либо «состояние НОРМА/ОТКАЗ», либо «реверсивные накопители» если стоит исполнение `R`
- **Нужна сверка с ModBus Universal.** До сверки — игнорировать V5..V8.

### 3.4 Логические каналы — привязка к точкам учёта

| Канал УРЖ | Регистр расхода | Регистр объёма | Точка установки |
|---:|---|---|---|
| 1 | 0x0000 | 0x0036 | питательная вода (вход) |
| 2 | 0x0002 | 0x0038 | пермеат товарный |
| 3 | 0x0004 | 0x003A | концентрат (дренаж) |
| 4 | 0x0006 | 0x003C | дренаж промывки / резерв |

## 4. Waveshare Modbus RTU **PWM Input 8CH** — 1 шт.

**Источник:** `doc/wsh ai.txt` (Secondary Development Protocol).

> ⚠️ **Это PWM Input 8CH, НЕ Analog Input 8CH.** Модуль измеряет **частоту PWM-сигнала и duty cycle** на 8 каналах — а не аналоговый ток 4–20 мА. Это меняет всё.

### 4.1 Параметры

| Параметр | Значение |
|---|---|
| Default slave | 1 |
| Назначено | **1** (без изменений) |
| Default baud | 9600 |
| Function codes | 0x03, 0x04, 0x06, 0x10 |
| Каналов | **8 PWM-входов** |

### 4.2 Карта регистров

**Каждый канал занимает 3 input-регистра** (FC 0x04):

| Channel | Freq HI (0x04) | Freq LO (0x04) | Duty (0x04) |
|:---:|:---:|:---:|:---:|
| 1 | 3x0000 | 3x0001 | 3x0002 |
| 2 | 3x0003 | 3x0004 | 3x0005 |
| 3 | 3x0006 | 3x0007 | 3x0008 |
| 4 | 3x0009 | 3x000A | 3x000B |
| 5 | 3x000C | 3x000D | 3x000E |
| 6 | 3x000F | 3x0010 | 3x0011 |
| 7 | 3x0012 | 3x0013 | 3x0014 |
| 8 | 3x0015 | 3x0016 | 3x0017 |

**Frequency** — uint32, big-endian (HI первым), unit `0.01 Hz`. По разным частям документа диапазон: либо 400..5_000_000 (4 Hz..50 kHz), либо 100..200_000_000 (1 Hz..2 MHz). Нужна экспериментальная проверка верхней границы.

**Duty cycle** — uint16, unit `0.01 %`, диапазон 0..1000 (0..100 %).

```c
// Читать 8 каналов: 24 регистра одним фреймом
// Команда: 01 04 00 00 00 18 F0 00
uint16_t raw[24];
modbus_read_input_registers(slave=1, addr=0x0000, count=24, raw);

for (int ch = 0; ch < 8; ch++) {
    uint32_t freq_units = ((uint32_t)raw[ch*3] << 16) | raw[ch*3 + 1];
    float freq_Hz = (float)freq_units / 100.0f;
    uint16_t duty_units = raw[ch*3 + 2];
    float duty_pct = (float)duty_units / 100.0f;
}
```

### 4.3 Holding-регистры конфигурации

| Адрес | Имя | R/W | Описание |
|---:|---|---|---|
| 4x2000 | UART params | RW (0x03/0x06) | HI = parity (0=None, 1=Odd, 2=Even); LO = baud (см. таблицу ниже) |
| 4x4000 | Device address | RW (0x03/0x06) | 0x0001..0x00FF |
| 4x8000 | Software version | R (0x03) | uint16, `BCD/100` (0x0064 = V1.00) |

**Коды baudrate (LO of 4x2000):**

| Code | Baud |
|---:|---:|
| 0x00 | 4800 |
| 0x01 | 9600 |
| 0x02 | 19200 |
| 0x03 | 38400 |
| 0x04 | 57600 |
| 0x05 | 115200 |
| 0x06 | 128000 |
| 0x07 | 256000 |

### 4.4 Где использовать PWM Input в РО-установке

Модуль PWM Input измеряет **частотные** сигналы. Применимо к:
- **Импульсные расходомеры** (счётчики-водомеры с открытым коллектором) — частота ~ расход
- **Тахометры** двигателей насосов — Hz пропорционально RPM
- **Датчики давления с PWM-выходом** (редко, но есть промышленные с 0..2 kHz)
- **Уровнемеры с частотным выходом** (редко)

⚠️ **Стандартные датчики давления 4–20 мА к этому модулю НЕ подключаются.** Нужен либо отдельный модуль `Modbus RTU Analog Input 8CH`, либо переход на датчики с PWM/частотным выходом.

### 4.5 Логические каналы (предположительно — согласовать)

| Канал PWM | Сигнал | Диапазон f | Формула |
|---:|---|---|---|
| 1 | Тахометр НД-насоса | 0..200 Hz | `RPM = f * 60 / pulses_per_rev` |
| 2 | Тахометр ВД-насоса | 0..200 Hz | то же |
| 3 | Импульсный счётчик питательной (резерв если УРЖ2КМ канал 1 не работает) | 0..1 kHz | `Q = K * f` (K из паспорта водомера) |
| 4..8 | Резерв | — | — |

> **Открытый вопрос:** какие именно PWM-сигналы заказчик планирует завести на этот модуль? Если планы измерения давления — нужен **Analog Input 8CH** (другой модуль), не PWM Input.

### 4.6 Команды записи (one-time setup)

```
# Сменить slave 1 → 2 (broadcast, при отключённых остальных)
00 06 40 00 00 02 [CRC]

# Установить baud 9600, parity None
00 06 20 00 00 01 42 1B

# Прочитать версию ПО
01 03 80 00 00 01 [CRC]   →   01 03 02 00 64 B9 AF   (V1.00)
```

## 5. KWS-306L (трёхфазный счётчик электроэнергии) — 2 шт.

**Источник:** карта регистров от заказчика. ⚠️ **Карта не полная** — для 3-фазного счётчика типично есть фазные напряжения U1/U2/U3, фазные токи I1/I2/I3, реактивная/полная мощность Q/S, частота Hz, PF; их нужно дополнить через datasheet поставщика.

### 5.1 Параметры

| Параметр | Значение |
|---|---|
| Default slave | 1 |
| Назначено | **20** (НД-насос), **21** (ВД-насос) |
| Default baud | 9600 (типовое для KWS-серии) |
| Function code | 0x03 (read holding), 0x06 (write single — для управления реле) |

### 5.2 Карта регистров (от заказчика)

| Holding (HEX) | Holding (DEC) | Параметр | Тип | Множитель → физ. ед. |
|---:|---:|---|---|---|
| 0x000E | 14 | Voltage (фазное?) | uint16 | × 0.1 → В (например, 2300 = 230.0 В) |
| 0x0010 | 16 | Current | uint16 | × 0.001 → А (например, 500 = 0.5 А) |
| 0x0012 | 18 | Power (active) | uint16 | × 0.1 → Вт |
| 0x001A | 26 | Energy | uint16 ⚠️ | × 0.01 → кВт·ч (иногда × 0.001) |
| 0x001B | 27 | Temperature | uint16 | × 1 → °C |
| 0x003F | 63 | Реле управления | uint16 | 1 = Вкл, 0 = Выкл (FC 0x06) |

⚠️ **Открытые вопросы по карте:**
1. **Energy = uint16?** При множителе 0.01 кВт·ч это даёт максимум 655 кВт·ч и переполнение. Скорее всего, energy = uint32 (2 регистра 0x001A + 0x001B), а температура — где-то в другом месте. Нужен datasheet.
2. **Voltage** — это сумма фаз, фаза A, или среднее? Для 3-фазного счётчика нужны 3 регистра (U1/U2/U3) для контроля перекоса фаз.
3. **Current** — то же: для 3-фазного нужны I1/I2/I3.
4. **Power** — активная P, реактивная Q, полная S? Один регистр × 0.1 Вт даёт max ~6.5 кВт — мало для ВД-насоса 4..7.5 кВт. Возможно P = uint32 в 2 регистрах.

**Адреса 0x0000..0x000D и 0x0013..0x0019** — не описаны в полученной карте. Они либо зарезервированы, либо содержат фазные значения. **Действие:** при первом подключении опросить блок 0x0000..0x0040 целиком, сравнить с показаниями LCD прибора, восстановить полную карту.

### 5.3 Команды

```c
// Прочитать все известные параметры одним фреймом (0x000E..0x001B = 14 регистров)
01 03 00 0E 00 0E [CRC]

// Включить реле (например, размыкание — отключение нагрузки KWS = аварийное отключение насоса)
01 06 00 3F 00 00 [CRC]

// Включить реле обратно
01 06 00 3F 00 01 [CRC]
```

⚠️ **Реле KWS как защитный размыкатель** — отдельный механизм аварийного обесточивания насоса. Использовать только при критичных алармах (E-STOP, перегрев насоса по температуре в KWS reg 0x001B). НЕ использовать как штатный SAFE-shutoff — для этого есть DO TCA9554.

### 5.4 Логические сигналы

| Сигнал | Slave | Регистр | Применение в SM |
|---|---:|---|---|
| Voltage НД | 20 | 0x000E | Если < 200 V или > 250 V → ALARM 1PH_VOLTAGE_OOR (для 1-фазного НД-насоса) |
| Current НД | 20 | 0x0010 | Если == 0 в состоянии AUTO_RUNNING → INTERLOCK_PUMP1_NO_CURRENT (зам. 4-20мА давления) |
| Power НД | 20 | 0x0012 | Учёт kWh, аномальное P > 1.2 × P_nominal → перегруз |
| Energy НД | 20 | 0x001A | Накопление в NVS, публикация в MQTT для биллинга |
| Temperature НД | 20 | 0x001B | Если > 80 °C → ALARM_OVER_TEMP, размыкаем реле KWS |
| Voltage/Current/Power/Energy/Temp ВД | 21 | 0x000E..0x001B | то же для ВД-насоса |

### 6.5 Дискретные выходы (DO через TCA9554, **не Modbus**)

> Подтверждено заказчиком: **дозатор управляется через DO** (релейный выход на TCA9554), не через Modbus и не через AO.

Текущая карта DO (см. `components/board_hal/include/board_config.h` или `process_signals.h`):
- DO0 — клапан подачи питательной
- DO1 — клапан перед мембранами
- DO2 — насос НД (вкл/выкл) — дублирует контроль через KWS-306L #20
- DO3 — насос ВД (вкл/выкл) — дублирует через KWS-306L #21
- DO4 — клапан дренажа концентрата
- DO5 — клапан промывки
- DO6 — **дозатор реагента / биоцида** (импульсное вкл/выкл по таймеру)
- DO7 — резерв (зуммер? световой сигнал?)

> Логику дозатора в режиме WASHING — см. TODO в `README.md`.

## 9. Рекомендуемый план интеграции

### Этап 1 — Перенастройка устройств на стенде (физический доступ)

1. **УРЖ2КМ:** меню → подрежим 03 = RTU, подрежим 04 = 9600, подрежим 05 = `002` (адрес).
2. **СЛ21 #1:** меню → МВ интерфейс → Адрес = `010`, Скорость = 9600 бод, Паритет = чётный (если нет None).
3. **СЛ21 #2:** меню → МВ интерфейс → Адрес = `011`, Скорость = 9600 бод, Паритет = чётный.
4. **Waveshare PWM Input 8CH:** оставить адрес 1, baud 9600 (default).
5. **KWS-306L #1 (НД):** broadcast `00 06 40 00 00 14` (адрес 20).
6. **KWS-306L #2 (ВД):** при отключённом #1 — broadcast `00 06 40 00 00 15` (адрес 21).

### Этап 2 — Реверс-инжиниринг

1. **УРЖ2КМ:** прогнать ModBus Universal от ТЕСС, получить точную карту регистров F1..F4 / V1..V4 / T1..T4 / o1..o4. Зафиксировать в этом документе.
2. **KWS-306L:** опросить holding 0x0000..0x0040 через ModScan / `mbpoll`, сравнить с LCD прибора, восстановить полную карту U1/U2/U3, I1/I2/I3, P/Q/S, Hz, PF.

### Этап 3 — Изменения в коде

1. `components/board_hal/include/board_config.h`:
   ```c
   #define MB_ADDR_WAVESHARE_PWM   1   /* был MB_ADDR_WAVESHARE_AI */
   #define MB_ADDR_URZH2KM         2
   #define MB_ADDR_SL21_201        10
   #define MB_ADDR_SL21_101        11
   #define MB_ADDR_KWS_PUMP_LP     20  /* НОВОЕ */
   #define MB_ADDR_KWS_PUMP_HP     21  /* НОВОЕ */
   ```
2. `components/modbus_poller/include/modbus_poller.h`: новые CID:
   ```c
   typedef enum {
       CID_PWM_CHANNELS = 0,         /* slave 1, input 0x0000..0x0017, 24 регистра */
       CID_FLOW_RATES,               /* slave 2, holding 0x0000..0x0007, 8 регистров (4 float) */
       CID_FLOW_VOLUMES,             /* slave 2, holding 0x0036..0x003D, 8 регистров (4 float) */
       CID_COND_ADDR10,              /* slave 10, holding 0x0000..0x0005, 6 регистров */
       CID_COND_ADDR11,              /* slave 11, holding 0x0000..0x0005, 6 регистров — БЫЛО 3 */
       CID_KWS_PUMP_LP,              /* slave 20, holding 0x000E..0x001B, 14 регистров */
       CID_KWS_PUMP_HP,              /* slave 21, holding 0x000E..0x001B, 14 регистров */
       CID_COUNT
   } modbus_cid_t;
   ```
3. **Удалить** `analog_input.c` или **переписать** в `pwm_input.c` (новая семантика — 24 регистра, freq+duty per channel).
4. **Создать** `components/drivers/power_meter.c` для KWS-306L.
5. **Расширить** `conductivity.c` на 4 канала (вместо текущих 3).
6. **Сократить** `flowmeter.c` чтение объёмов с 16 до 8 регистров (V5..V8 пока пропустить до сверки).

### Этап 4 — Интеграция в SM и алярмы

1. `interlocks.h`: новые биты `INTERLOCK_PUMP_LP_NO_CURRENT`, `INTERLOCK_PUMP_HP_NO_CURRENT`, `INTERLOCK_PUMP_OVERTEMP`, `INTERLOCK_VOLTAGE_OOR`.
2. `alarm_manager.h`: новые коды `ALARM_KWS_*`.
3. `state_machine.c::update_auto`: проверка current/voltage/temp от KWS перед переходом в RUNNING; авто-fault при перегреве.
4. **Если PWM Input не для давления** — пересмотреть весь блок «контроль давления» (P1..P4 берётся откуда тогда?).

### Этап 5 — Телеметрия

1. `mqtt_publish.c`: добавить топики `power/lp/{voltage,current,power,energy,temp}`, `power/hp/{...}`, `pwm/ch{1..8}/{freq,duty}`.
2. `web_api_status.c`: добавить новые поля JSON.
3. HA discovery (`mqtt_discovery.c`): сенсоры для kWh, V, A, °C — для интеграции с Home Assistant.
