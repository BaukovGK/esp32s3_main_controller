# ТЕХНИЧЕСКОЕ ЗАДАНИЕ НА ПРОШИВКУ
# Контроллер установки обратного осмоса

**Версия:** 2.0  
**Дата:** 2026-02-04  
**Платформа:** ESP32-S3 (ESP-IDF 5.x)

---

## ОБЩИЕ ТРЕБОВАНИЯ

### Целевая платформа
- **MCU:** ESP32-S3 dual-core 240MHz
- **Память:** 16MB Flash, 8MB PSRAM
- **ОС:** FreeRTOS
- **Фреймворк:** ESP-IDF 5.x

### Критерии качества
- Время реакции на аварийный стоп: < 50 мс
- Время цикла основной логики: < 100 мс
- Uptime без перезагрузки: > 30 дней
- Восстановление после сбоя питания: автоматическое

### МОДУЛЬ 1: HAL — Аппаратная абстракция

**Файлы:** `hal/gpio.c`, `hal/uart.c`, `hal/spi.c`, `hal/ethernet.c`, `hal/nvs_storage.c`

**Задачи:**

1. **GPIO**
   - Инициализация 8 DI (входы с подтяжкой)
   - Инициализация 8 DO (выходы)
   - Debounce для DI (50 мс)
   - API: `hal_gpio_read_di()`, `hal_gpio_write_do()`

2. **UART RS-485**
   - Конфигурация: 115200 8N1
   - Управление направлением (DE/RE)

3. **Ethernet W5500**
   - SPI-интерфейс
   - DHCP или статический IP

4. **NVS Storage**
   - Чтение/запись конфигурации
   - Атомарные операции

**Критерии приёмки:**
- DI читаются с debounce
- DO переключаются за < 1 мс
- Ethernet получает IP
- NVS сохраняет данные между перезагрузками

### МОДУЛЬ 2: Драйвер Modbus Master

**Файлы:** `drivers/modbus_master.c`, `drivers/modbus_master.h`

**Задачи:**

1. **Базовый протокол**
   - Modbus RTU (CRC16)
   - Функции: 0x03, 0x04, 0x06
   - Таймауты и повторы

2. **Менеджер опроса**
   - Циклический опрос по расписанию
   - Разные периоды для разных устройств

**Расписание опроса:**

| Устройство     | Адрес | Период  | Регистры                  |
|----------------|-------|---------|---------------------------|
| Waveshare AI   | 1     | 100 мс  | 0x0000-0x0007 (func 0x04) |
| УРЖ2КМ расход  | 2     | 1000 мс | 0x0000-0x0007 (func 0x03) |
| УРЖ2КМ объём   | 2     | 2000 мс | 0x0036-0x0045 (func 0x03) |
| СЛ21 (addr 10) | 10    | 3000 мс | 0x0001-0x0006 (func 0x03) |
| СЛ21 (addr 11) | 11    | 3000 мс | 0x0001-0x0003 (func 0x03) |

**Критерии приёмки:**
- Все устройства опрашиваются по расписанию
- Ошибки не блокируют опрос других устройств

### МОДУЛЬ 3: Драйвер расходомера УРЖ2КМ

**Файлы:** `drivers/flowmeter_urzh2km.c`, `drivers/flowmeter_urzh2km.h`

**Задачи:**

1. **Конвертация float** — нестандартный формат (байты переставлены)

2. **Структуры данных**
   ```c
   typedef struct {
       float flow_m3h[4];      // Q1-Q4
       double volume_m3[4];
       uint32_t runtime_min[4];
       uint32_t status;
       bool channel_ok[4];
   } urzh2km_data_t;
   ```

3. **Назначение каналов**
   - Q1: Входной расход (после преднагнетания)
   - Q2: Рецикл концентрата 1-й ст.
   - Q3: Пермеат 2-й ст.
   - Q4: Концентрат 2-й ст.

**Критерии приёмки:**
- Расход читается корректно (проверка float)
- Флаги отказов распознаются

### МОДУЛЬ 8: Логика режима AUTO

**Файлы:** `process/auto_mode.c`, `process/auto_mode.h`

**Последовательность пуска:**
1. Проверка блокировок
2. Запуск насоса преднагнетания
3. Ожидание: подтверждение (3 сек) + разгон УПП (15 сек)
4. Запуск насоса 1-й ступени
5. Ожидание заполнения промежуточной
6. Запуск насоса 2-й ступени
7. Запуск дозатора (если timer mode)

**Регулирование по ёмкостям:**

| Событие | Действие |
|---------|----------|
| DI1=0 (исходная пустая) | Останов преднагн. + 1-я ст., 2-я продолжает |
| DI3=1 (промежут. полная) | Пауза преднагн. + 1-й ст. |
| DI2=0 (промежут. пустая) | Останов 2-й ст. |
| DI4=1 (пермеатная полная) | Останов 2-й ст. |

**Критерии приёмки:**
- Насосы запускаются в правильной последовательности
- Регулирование по уровням работает

### МОДУЛЬ 9: Логика режима WASHING

**Файлы:** `process/washing_mode.c`, `process/washing_mode.h`

**Фазы:**
1. Нагрев (30 мин) — преднагн. ВКЛ, нагреватель с гистерезисом
2. Подача (20 мин) — ручные клапаны
3. Слив — подтверждение оператора

**Управление нагревателем:**
```
T < (target - 2°C) → ВКЛ
T ≥ target → ВЫКЛ
T > max → АВАРИЯ
```

**Примечание:** Насос-дозатор НЕ работает в WASHING.

**Критерии приёмки:**
- Температура регулируется с гистерезисом
- Защита от перегрева работает

### МОДУЛЬ 11: Драйвер насоса-дозатора

**Файлы:** `drivers/doser.c`, `drivers/doser.h`

**Режимы:**

| Режим  | Поведение |
|--------|-----------|
| manual | По команде |
| timer  | N минут работы за M минут цикла |

**Логика таймера:**
```
Цикл M минут:
├── [0 ... N] — ВКЛ
└── [N ... M] — ВЫКЛ

Условия:
- Режим AUTO
- doser_enabled = true
- doser_mode = timer
```

**Состояния:**
```
DOSER_OFF ──► DOSER_RUNNING ──► DOSER_PAUSE ──► DOSER_OFF
```

**API:**
```c
void doser_init(void);
void doser_process(void);  // Вызывается каждые 100 мс
void doser_cmd_on(void);
void doser_cmd_off(void);
bool doser_is_running(void);
uint32_t doser_get_cycle_remaining(void);
```

**Критерии приёмки:**
- Таймерный режим работает корректно
- Не включается в режиме WASHING

### МОДУЛЬ 12: Менеджер блокировок

**Файлы:** `process/interlock_manager.c`, `process/interlock_manager.h`

**Матрица блокировок:**

| Блокировка         | Условие         | Реакция |
|--------------------|-----------------|---------|
| E-STOP             | DI5=0           | Останов ВСЕХ |
| Сухой ход исходной | DI1=0           | Останов преднагн. + 1-я ст. |
| Сухой ход промежут.| DI2=0           | Останов 2-й ст. |
| Превышение P1      | P1 > 5.5 bar    | Останов преднагнетания |
| Превышение P3      | P3 > 35 bar     | Останов 1-й ступени |
| Превышение P4      | P4 > 8 bar      | Останов 2-й ступени |
| Засорение фильтра  | P1-P2 > 1.0 bar | WARNING |
| Перегрев           | T > 45°C        | Откл. нагревателя |

**Критерии приёмки:**
- E-STOP срабатывает < 50 мс
- Гистерезис уровней предотвращает ложные срабатывания

### МОДУЛЬ 15: Сервис телеметрии

**Файлы:** `services/telemetry.c`, `services/telemetry.h`

**Расчёты:**

| Параметр | Формула |
|----------|---------|
| Расход на мембрану 1-й ст. | Q1 + Q2 |
| Recovery 2-й ступени | Q3 / (Q3 + Q4) × 100% |
| Общий выход системы | Q3 / Q1 × 100% |
| Перепад на фильтре | P1 - P2 |
| Селективность 1-й ст. | (σ1 - σ2) / σ1 × 100% |
| Селективность 2-й ст. | (σ2 - σ3) / σ2 × 100% |

**Критерии приёмки:**
- Все параметры собираются
- Расчёты корректны
- JSON валиден
