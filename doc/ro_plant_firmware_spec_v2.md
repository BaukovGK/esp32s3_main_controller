# ТЕХНИЧЕСКОЕ ЗАДАНИЕ НА ПРОШИВКУ
# Контроллер установки обратного осмоса

**Версия:** 2.0  
**Дата:** 2026-02-04  
**Платформа:** ESP32-S3 (ESP-IDF 5.x)

---

## ОБЩИЕ ТРЕБОВАНИЯ

### Целевая платформа
- **MCU:** ESP32-S3 dual-core 240MHz
- **Память:** 16MB Flash, 8MB PSRAM
- **ОС:** FreeRTOS
- **Фреймворк:** ESP-IDF 5.x

### Критерии качества
- Время реакции на аварийный стоп: < 50 мс
- Время цикла основной логики: < 100 мс
- Uptime без перезагрузки: > 30 дней
- Восстановление после сбоя питания: автоматическое

### МОДУЛЬ 1: HAL — Аппаратная абстракция

**Файлы:** `hal/gpio.c`, `hal/uart.c`, `hal/spi.c`, `hal/ethernet.c`, `hal/nvs_storage.c`

**Задачи:**

1. **GPIO**
   - Инициализация 8 DI (входы с подтяжкой)
   - Инициализация 8 DO (выходы)
   - Debounce для DI (50 мс)
   - API: `hal_gpio_read_di()`, `hal_gpio_write_do()`

2. **UART RS-485**
   - Конфигурация: 115200 8N1
   - Управление направлением (DE/RE)

3. **Ethernet W5500**
   - SPI-интерфейс
   - DHCP или статический IP

4. **NVS Storage**
   - Чтение/запись конфигурации
   - Атомарные операции

**Критерии приёмки:**
- DI читаются с debounce
- DO переключаются за < 1 мс
- Ethernet получает IP
- NVS сохраняет данные между перезагрузками

### МОДУЛЬ 5: Драйвер Waveshare Analog Input

**Файлы:** `drivers/analog_input.c`, `drivers/include/analog_input.h`

**Задачи:**

1. **Масштабирование каналов**

| Канал | Min | Max | Единицы | Назначение                |
|-------|-----|-----|---------|---------------------------|
| AI1   | 0   | 6   | bar     | P1 — после преднагнетания |
| AI2   | 0   | 6   | bar     | P2 — после фильтра        |
| AI3   | 0   | 40  | bar     | P3 — после насоса 1-й ст. |
| AI4   | 0   | 10  | bar     | P4 — после насоса 2-й ст. |
| AI5   | 0   | 100 | °C      | Температура               |

   **Формула преобразования** (модуль Waveshare в режиме 4–20 мА возвращает raw в **микроамперах**, диапазон 4000..20000):
   ```
   mA    = raw_uA / 1000
   ratio = (mA − 4) / 16            (clamp 0..1)
   value = range_min + ratio × (range_max − range_min)
   ```
   Источник: `doc/wsh ai.txt` (Development Protocol V2) + Arduino-демо `doc/waveshare_ai_ref/`.

2. **Фильтрация** — скользящее среднее (N=8) на сырых значениях в мкА.

3. **Детекция отказа датчика (sensor-fault на оба конца):**
   - `raw_uA < 3500` (< 3.5 мА) → обрыв токовой петли
   - `raw_uA > 20500` (> 20.5 мА) → короткое замыкание / переходный процесс
   - При `fault` поле `value` = NaN, `raw_ma` остаётся валидным для диагностики
   - Зоны 3.5..4.0 и 20.0..20.5 мА — производственный допуск (±0.5 мА), не считается fault, ratio клипуется к 0/1.

**Критерии приёмки:**
- Значения масштабируются корректно (P3 при 20 мА = 40 бар, P1 при 12 мА = 3 бар)
- Обрыв датчика (< 3.5 мА) детектируется → `analog_input_is_fault() == true`, `value == NaN`
- КЗ датчика (> 20.5 мА) детектируется аналогично

### МОДУЛЬ 5а: Драйвер счётчиков электроэнергии KWS-306L

**Файлы:** `drivers/power_meter.c`, `drivers/include/power_meter.h`

**Задачи:**

1. **Опрос двух идентичных приборов** (одна карта регистров, разные slave-адреса):

| Pump ID | Slave | Назначение |
|---------|-------|------------|
| `PUMP_LP` | 20 | НД-насос (низкое давление, насос подачи) |
| `PUMP_HP` | 21 | ВД-насос (высокое давление, насос RO) |

2. **Карта регистров** — один блок FC 0x03, 14 регистров `0x000E..0x001B`:

| Регистр | Поле        | Тип    | Скейл  | Единицы |
|---------|-------------|--------|--------|---------|
| 0x000E  | voltage     | uint16 | × 0.1  | В       |
| 0x0010  | current     | uint16 | × 0.001| А       |
| 0x0012  | power       | uint16 | × 0.1  | Вт      |
| 0x001A  | energy      | uint16 | × 0.01 | кВт·ч   |
| 0x001B  | temperature | uint16 | × 1    | °C      |

3. **Управление реле** — регистр `0x003F` через FC 0x06 (write single register). **TODO в следующей фазе** — на текущий момент только READ.

4. **TODO datasheet KWS-306L** (см. `power_meter.h`): уточнить трёхфазную карту регистров (в текущей карте только один канал U/I/P) и точный формат поля energy (вероятно 0x001A+0x001B = uint32, а не uint16 + temperature).

**Критерии приёмки:**
- U/I/P/E/T читаются для обоих slave (20, 21)
- `power_meter_is_online(pump)` корректно отражает статус через `modbus_poller_is_device_online()`
- Опрос происходит раз в 2 секунды (`MB_POLL_PERIOD_KWS_MS`)

### МОДУЛЬ 8: Логика режима AUTO

**Файлы:** `process/auto_mode.c`, `process/auto_mode.h`

**Последовательность пуска:**
1. Проверка блокировок
2. Запуск насоса преднагнетания
3. Ожидание: подтверждение (3 сек) + разгон УПП (15 сек)
4. Запуск насоса 1-й ступени
5. Ожидание заполнения промежуточной
6. Запуск насоса 2-й ступени
7. Запуск дозатора (если timer mode)

**Регулирование по ёмкостям:**

| Событие | Действие |
|---------|----------|
| DI1=0 (исходная пустая) | Останов преднагн. + 1-я ст., 2-я продолжает |
| DI3=1 (промежут. полная) | Пауза преднагн. + 1-й ст. |
| DI2=0 (промежут. пустая) | Останов 2-й ст. |
| DI4=1 (пермеатная полная) | Останов 2-й ст. |

**Критерии приёмки:**
- Насосы запускаются в правильной последовательности
- Регулирование по уровням работает

### МОДУЛЬ 9: Логика режима WASHING

**Файлы:** `process/washing_mode.c`, `process/washing_mode.h`

**Фазы:**
1. Нагрев (30 мин) — преднагн. ВКЛ, нагреватель с гистерезисом
2. Подача (20 мин) — ручные клапаны
3. Слив — подтверждение оператора

**Управление нагревателем:**
```
T < (target - 2°C) → ВКЛ
T ≥ target → ВЫКЛ
T > max → АВАРИЯ
```

**Примечание:** Насос-дозатор НЕ работает в WASHING.

### МОДУЛЬ 11: Драйвер насоса-дозатора

**Файлы:** `drivers/doser.c`, `drivers/doser.h`

**Режимы:**

| Режим  | Поведение |
|--------|-----------|
| manual | По команде |
| timer  | N минут работы за M минут цикла |

**Логика таймера:**
```
Цикл M минут:
├── [0 ... N] — ВКЛ
└── [N ... M] — ВЫКЛ

Условия:
- Режим AUTO
- doser_enabled = true
- doser_mode = timer
```

**Состояния:**
```
DOSER_OFF ──► DOSER_RUNNING ──► DOSER_PAUSE ──► DOSER_OFF
```

**API:**
```c
void doser_init(void);
void doser_update(bool auto_running);  // 100мс из process_task
void doser_enable(bool en);
bool doser_is_enabled(void);
doser_state_t doser_get_state(void);
```

**Критерии приёмки:**
- Таймерный режим работает корректно
- Не включается в режиме WASHING
