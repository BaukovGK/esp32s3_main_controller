# alarm_manager -- Менеджер аварий и предупреждений

## Описание

Модуль `alarm_manager` реализует централизованную систему регистрации, дедупликации и хранения аварий и предупреждений установки обратного осмоса. Поддерживает четыре категории серьезности: CRITICAL, ALARM, WARNING, INFO. Аварии хранятся в массиве активных аварий и в кольцевом буфере истории. Счетчик ID персистентен через NVS. Модуль уведомляет зарегистрированные callback-функции (до 4 штук) при каждом событии -- установке или снятии аварии.

**Файлы:**
- Заголовочный: `include/alarm_manager.h`
- Реализация: `alarm_manager.c`

## Перечисления (enum)

### `alarm_category_t` -- Категории аварий

| Значение            | Числовое | Описание                                                             |
|---------------------|----------|----------------------------------------------------------------------|
| `ALARM_CAT_CRITICAL`| 0        | Критическая авария -- требуется немедленная остановка установки       |
| `ALARM_CAT_ALARM`   | 1        | Авария -- требует внимания оператора                                 |
| `ALARM_CAT_WARNING` | 2        | Предупреждение -- нештатная ситуация, работа может продолжаться      |
| `ALARM_CAT_INFO`    | 3        | Информационное событие -- запись в журнал без активной аварии         |

**Особенности:** События категории `ALARM_CAT_INFO` не дедуплицируются (каждый вызов `alarm_raise` создает новую запись) и не помещаются в массив активных аварий (только в историю).

## Структуры данных

### `alarm_entry_t` -- Запись аварии

| Поле           | Тип                | Описание                                                              |
|----------------|--------------------|-----------------------------------------------------------------------|
| `id`           | `uint32_t`         | Уникальный порядковый номер записи (монотонно возрастает, персистентен через NVS) |

```c

```

Указатель на функцию, вызываемую при каждом событии (подъем или снятие аварии). Принимает указатель на запись аварии. Используется для уведомления подсистем MQTT, веб-интерфейса и т.д.

## Внутренние (static) функции

### `history_push`

```c
static void history_push(const alarm_entry_t *entry)
```

**Описание:** Добавляет запись аварии в кольцевой буфер истории. Запись копируется в позицию `s_history_head`, после чего голова буфера сдвигается на следующую позицию (по модулю `MAX_HISTORY`). Если буфер ещё не заполнен, счетчик `s_history_count` увеличивается. При переполнении самая старая запись перезаписывается.

**Параметры:**
- `entry` -- указатель на запись аварии для добавления в историю

---

### `notify_all`

```c
static void notify_all(const alarm_entry_t *entry)
```

**Описание:** Вызывает все зарегистрированные callback-функции, передавая им указатель на запись аварии. Проверяет каждый callback на `NULL` перед вызовом.

**Параметры:**
- `entry` -- указатель на запись аварии

---

### `save_id_to_nvs`

```c
static void save_id_to_nvs(void)
```

**Описание:** Сохраняет текущее значение счетчика `s_next_id` в NVS по ключу `"alm_id"`. Вызывается периодически (каждые `NVS_SAVE_INTERVAL` аварий) или немедленно при критической аварии. Это обеспечивает непрерывную нумерацию аварий после перезагрузки устройства.

**Параметры:** нет

---

### `find_active_by_code`

```c
static int find_active_by_code(alarm_code_t code)
```

**Описание:** Выполняет линейный поиск аварии с указанным кодом в массиве активных аварий `s_active`.

**Параметры:**
- `code` -- код аварии для поиска

**Возвращает:** Индекс найденной записи (0..`s_active_count`-1) или `-1`, если авария с таким кодом не найдена среди активных.

## Публичные функции

### `alarm_manager_init`

```c
esp_err_t alarm_manager_init(void);
```

**Описание:** Инициализирует менеджер аварий. Выполняет следующие действия:

1. Обнуляет все внутренние счетчики и массивы (`s_active_count`, `s_history_head`, `s_history_count`, `s_cb_count`, `s_save_counter`).
2. Загружает счетчик ID из NVS по ключу `"alm_id"`. Если ключ не найден или значение <= 0, счетчик начинается с 1.
3. Логирует факт инициализации с текущим значением `next_id`.
4. Регистрирует информационное событие `ALARM_SYSTEM_START` (категория `ALARM_CAT_INFO`, значение 0) -- отметка о старте системы.

**Параметры:** нет

**Возвращает:** `ESP_OK` -- всегда.

---

### `alarm_manager_register_notify`

```c
esp_err_t alarm_manager_register_notify(alarm_notify_cb_t cb);
```

**Описание:** Регистрирует callback-функцию для уведомления о событиях аварий. Максимально допускается 4 callback-функции. Callback вызывается как при подъеме, так и при снятии аварии.

**Параметры:**
- `cb` -- указатель на функцию обратного вызова типа `alarm_notify_cb_t`

**Возвращает:**
- `ESP_OK` -- callback успешно зарегистрирован
- `ESP_ERR_INVALID_ARG` -- передан `NULL`
- `ESP_ERR_NO_MEM` -- достигнуто максимальное число callback-ов (`MAX_CALLBACKS`)

---

### `alarm_raise`

```c
void alarm_raise(alarm_code_t code, alarm_category_t cat, float value);
```

**Описание:** Поднимает (регистрирует) аварию с указанным кодом, категорией и опциональным числовым значением. Алгоритм работы:

1. **Дедупликация:** Если категория не `ALARM_CAT_INFO`, выполняется поиск активной аварии с тем же кодом. Если найдена -- вызов игнорируется (возврат без действий). Для INFO-событий дедупликация не применяется -- каждый вызов создает новую запись.
2. **Создание записи:** Формируется `alarm_entry_t` с уникальным ID (из `s_next_id++`), текущей временной меткой, переданными параметрами и флагом `active = true`.
3. **Добавление в активные:** Если категория не `ALARM_CAT_INFO` и массив не переполнен (`< MAX_ACTIVE`), запись добавляется в `s_active`.
4. **Добавление в историю:** Запись всегда добавляется в кольцевой буфер истории.
5. **Логирование:** Выводится предупреждение с категорией, кодом, значением и ID.
6. **Уведомление:** Вызываются все зарегистрированные callback-функции.
7. **Сохранение ID:** Счетчик сохранений увеличивается. Если достигнут `NVS_SAVE_INTERVAL` или категория `ALARM_CAT_CRITICAL`, ID сохраняется в NVS немедленно.

**Параметры:**
- `code` -- код аварии (`alarm_code_t`)
- `cat` -- категория серьезности (`alarm_category_t`)
- `value` -- числовое значение (например, текущее давление); 0 если не применимо

---

### `alarm_clear`

```c
void alarm_clear(alarm_code_t code);
```

**Описание:** Снимает (деактивирует) ранее поднятую аварию по ее коду. Алгоритм работы:

1. Ищет аварию с указанным кодом в массиве активных. Если не найдена -- возврат без действий.
2. Создает запись о снятии: новый уникальный ID, текущая временная метка, категория из оригинальной аварии, `value = 0`, `active = false`.
3. Удаляет запись из массива активных сдвигом элементов (массив сжимается).
4. Добавляет запись о снятии в кольцевой буфер истории.
5. Логирует факт снятия аварии.
6. Уведомляет все зарегистрированные callback-функции.

**Параметры:**
- `code` -- код аварии для снятия

---

### `alarm_get_active`

```c
int alarm_get_active(alarm_entry_t *out, int max_cnt);
```

**Описание:** Копирует список текущих активных аварий в предоставленный буфер. Количество скопированных записей ограничено как числом активных аварий, так и размером буфера.

**Параметры:**
- `out` -- буфер-приемник для записей аварий
- `max_cnt` -- максимальное число записей, которое может вместить буфер

**Возвращает:** Фактическое число скопированных записей (0..min(`s_active_count`, `max_cnt`)).

---

### `alarm_get_history`

```c
int alarm_get_history(alarm_entry_t *out, int max_cnt);
```

**Описание:** Копирует записи из кольцевого буфера истории в предоставленный буфер. Возвращает последние (самые свежие) записи. Алгоритм:

1. Определяет количество записей для копирования: `min(s_history_count, max_cnt)`.
2. Вычисляет начальную позицию в кольцевом буфере: если буфер ещё не заполнен целиком, начало = 0; иначе начало = `s_history_head` (самая старая запись).
3. Пропускает самые старые записи, если `s_history_count > cnt`, и копирует последние `cnt` записей с учетом кольцевой адресации.

**Параметры:**
- `out` -- буфер-приемник для записей аварий
- `max_cnt` -- максимальное число записей

**Возвращает:** Фактическое число скопированных записей. Возвращает 0, если `out == NULL` или `max_cnt <= 0`.

| `alm_id`  | int32  | Персистентный счетчик ID аварий (загружается при старте, сохраняется периодически) |
