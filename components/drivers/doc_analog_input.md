# Документация: analog_input (Драйвер аналоговых входов)

**Файлы:**
- Заголовочный: `include/analog_input.h`
- Реализация: `analog_input.c`

---

## Общее описание

Драйвер аналоговых входов для модуля **Waveshare Modbus RTU Analog Input 8CH (A)** (8-канальный модуль аналогового ввода с интерфейсом Modbus). Модуль настроен в режиме 3 (4–20 мА), в котором сырое значение из input-регистра возвращается **напрямую в микроамперах** (4 мА = 4000, 20 мА = 20000).

**Источники документации:**
- `doc/wsh ai.txt` — Development Protocol V2 модуля Waveshare AI.
- `doc/waveshare_ai_ref/Modbus_RTU_Analog_Input.ino` — справочный Arduino-демо производителя.

Раздел Software Test → Modbus Poll wiki производителя: «displays the current by default, and the unit is uA». Если jumper'ы переведены в другой режим (mode 0/1 — вольтаж, mode 4 — scale code 0..4095), формула преобразования даст неверный результат.

Драйвер выполняет следующие задачи:
1. Получение сырых данных из Modbus-регистров через модуль `modbus_poller`.
2. Цифровая фильтрация методом скользящего среднего с окном N=8.
3. Преобразование сырых значений (мкА) в инженерные единицы (бар, градусы Цельсия) через нормализацию по диапазону 4..20 мА.
4. Пересчёт сырых значений в значения тока (мА) для диагностики.
5. Детекция обрыва датчика (ток ниже ~3.5 мА) и короткого замыкания (ток выше ~20.5 мА).
6. Контроль онлайн-статуса устройства на шине Modbus.

Используется в системе управления обратным осмосом для мониторинга давлений на различных ступенях и температуры воды.

| `AI_CH_P1` | `0` | Индекс канала P1 — давление после насоса подачи. Диапазон измерения: 0-6 бар. |
| `AI_CH_P2` | `1` | Индекс канала P2 — давление после фильтра. Диапазон измерения: 0-6 бар. |
| `AI_CH_P3` | `2` | Индекс канала P3 — давление после насоса 1-й ступени обратного осмоса. Диапазон измерения: 0-40 бар. |
| `AI_CH_P4` | `3` | Индекс канала P4 — давление после насоса 2-й ступени обратного осмоса. Диапазон измерения: 0-10 бар. |
| `AI_CH_T` | `4` | Индекс канала T — температура воды. Диапазон измерения: 0-100 градусов Цельсия. |

### Приватные (analog_input.c)

| Константа | Значение | Описание |
|-----------|----------|----------|
| `MA_WINDOW` | `8` | Размер окна скользящего среднего. Определяет количество последних отсчётов, по которым вычисляется среднее арифметическое для фильтрации шума АЦП. |
| `UA_AT_4MA` | `4000` | Сырое значение в микроамперах, соответствующее минимуму токовой петли 4 мА. Используется как «нулевой» сдвиг при нормализации: `ratio = (raw_uA − UA_AT_4MA) / UA_SPAN`. |
| `UA_AT_20MA` | `20000` | Сырое значение в микроамперах, соответствующее максимуму токовой петли 20 мА. Граница верхней нормы для расчёта `ratio = 1.0`. |
| `UA_SPAN` | `16000` | Размах (span) токовой петли в мкА: 20000 − 4000 = 16000 (16 мА). Делитель при нормализации raw в `ratio` 0..1. |
| `FAULT_BREAK_UA` | `3500` | Порог детекции обрыва токовой петли в микроамперах (3.5 мА). Если усреднённое raw < `FAULT_BREAK_UA` — нет «живого нуля» 4 мА → обрыв линии или неисправность датчика. Зона 3.5..4.0 мА — производственный допуск (±0.1 мА × 5), не считается fault. |
| `FAULT_SHORT_UA` | `20500` | Порог детекции короткого замыкания / переходного процесса в микроамперах (20.5 мА). Если усреднённое raw > `FAULT_SHORT_UA` — ток превышает допустимый максимум 20 мА → КЗ или ошибка датчика. Зона 20.0..20.5 мА — производственный допуск, не считается fault. |
| `AI_ENABLED_CHANNELS` | `5` | Количество активных (задействованных) каналов (P1, P2, P3, P4, T). Каналы с индексами от `AI_ENABLED_CHANNELS` до `AI_CHANNEL_COUNT - 1` считаются резервными и отключаются при инициализации (`enabled = false`). |

## Типы данных (typedef / struct)

### Публичные (analog_input.h)

#### `ai_channel_data_t`
Структура данных одного аналогового канала.

| Поле | Тип | Описание |
|------|-----|----------|
| `value` | `float` | Текущее измеренное значение в инженерных единицах. Для каналов давления — бар, для канала температуры — градусы Цельсия. Вычисляется по нормализованному отношению токовой петли: `value = range_min + ratio * (range_max - range_min)`. При обнаружении sensor fault (обрыв или КЗ) принимает значение `NAN`. |
| `raw_ma` | `float` | Текущее значение тока датчика в миллиамперах (мА). Вычисляется напрямую из микроамперного raw: `raw_ma = avg_uA / 1000.0f`. Публикуется всегда (даже при fault) для диагностики токовой петли. Нормальный диапазон: 4.0..20.0 мА. |
| `fault` | `bool` | Флаг неисправности датчика / токовой петли. `true` означает, что усреднённое raw < `FAULT_BREAK_UA` (3500 мкА) — обрыв линии, ИЛИ raw > `FAULT_SHORT_UA` (20500 мкА) — короткое замыкание / выход за допустимый диапазон. При `fault == true` поле `value` равно `NAN`. |
| `valid` | `bool` | Флаг актуальности данных. `true` означает, что устройство Waveshare AI онлайн (`device_online == true`) И нет sensor fault (`fault == false`). Если `valid == false`, значение `value` не следует использовать для управления. |

#### `ai_data_t`
Агрегированная структура данных всех аналоговых каналов.

| Поле | Тип | Описание |
|------|-----|----------|
| `channels` | `ai_channel_data_t[AI_CHANNEL_COUNT]` | Массив из 8 элементов — данные каждого аналогового канала. Индексация по константам `AI_CH_P1` ... `AI_CH_T`. Каналы с индексами от `AI_ENABLED_CHANNELS` (5) до `AI_CHANNEL_COUNT - 1` (7) зарезервированы и будут иметь `valid == false`. |
| `device_online` | `bool` | Флаг доступности устройства Waveshare AI 8CH на шине Modbus. `true` означает, что устройство отвечает на запросы. Определяется функцией `modbus_poller_is_device_online()`. |

### Приватные (analog_input.c)

#### `ai_ch_cfg_t`
Конфигурация одного аналогового канала (внутренняя структура, не экспортируется).

| Поле | Тип | Описание |
|------|-----|----------|
| `range_min` | `float` | Минимальное значение инженерной единицы, соответствующее минимуму токовой петли (raw_uA == `UA_AT_4MA`, ток 4 мА). Например, 0.0 бар для каналов давления. |
| `range_max` | `float` | Максимальное значение инженерной единицы, соответствующее максимуму токовой петли (raw_uA == `UA_AT_20MA`, ток 20 мА). Например, 6.0 бар для P1 и P2, 40.0 бар для P3, 10.0 бар для P4, 100.0 °C для T. |
| `enabled` | `bool` | Признак того, что канал активен и подлежит обработке. Каналы 0 .. `AI_ENABLED_CHANNELS - 1` (0-4) включены (`true`), каналы `AI_ENABLED_CHANNELS` .. `AI_CHANNEL_COUNT - 1` (5-7) выключены (`false`, резерв). Если `enabled == false`, данные канала не обрабатываются, а `valid` устанавливается в `false`. |

## Внутренние статические переменные (analog_input.c)

| Переменная | Тип | Описание |
|------------|-----|----------|
| `TAG` | `const char *` | Тег для системы логирования ESP-IDF. Значение: `"ai_drv"`. Используется во всех вызовах `ESP_LOGx()` для идентификации сообщений этого модуля. |

| `s_ma_filled` | `bool` | Флаг полного заполнения буфера скользящего среднего. Устанавливается в `true`, когда индекс `s_ma_idx` совершает полный оборот (возвращается к 0). До этого момента среднее вычисляется по фактически накопленным отсчётам (`s_ma_idx` элементов), после — по полному окну (`MA_WINDOW` элементов). |
| `s_data` | `ai_data_t` | Текущие обработанные данные всех аналоговых каналов. Обновляется при каждом вызове `analog_input_update()` атомарной публикацией снапшота под spinlock'ом. Копируется в пользовательский буфер через `analog_input_get_data()`. |
| `s_data_mux` | `portMUX_TYPE` | **Phase-4 (M-4):** spinlock для защиты `s_data` от гонок между писателем (`process_task` через `analog_input_update`) и читателями (`mqtt_task`, HTTP-сервер). Короткие критические секции (memcpy / чтение поля), не блокирующие. Инициализирован макросом `portMUX_INITIALIZER_UNLOCKED`. |

## Функции

### `void analog_input_init(void)`

**Объявление:** `analog_input.h`, строка 39

**Описание:**
Инициализация драйвера аналоговых входов. Должна быть вызвана один раз при старте системы перед использованием любых других функций модуля.

Выполняемые действия:
1. Настройка конфигурации каналов 0-4 (P1, P2, P3, P4, T) — задание диапазонов инженерных единиц и установка флага `enabled = true`:
   - P1 (канал 0): 0.0 - 6.0 бар
   - P2 (канал 1): 0.0 - 6.0 бар
   - P3 (канал 2): 0.0 - 40.0 бар
   - P4 (канал 3): 0.0 - 10.0 бар
   - T (канал 4): 0.0 - 100.0 °C
2. Отключение резервных каналов `AI_ENABLED_CHANNELS` .. `AI_CHANNEL_COUNT - 1` (5-7) в цикле (`enabled = false`).
3. Обнуление буфера скользящего среднего `s_ma_buf`.
4. Сброс индекса буфера `s_ma_idx = 0` и флага заполнения `s_ma_filled = false`.
5. Обнуление структуры данных `s_data`.
6. Вывод информационного сообщения в лог.

**Параметры:** нет

**Возвращаемое значение:** нет (`void`)

### `void analog_input_update(void)`

**Объявление:** `analog_input.h`, строка 40

**Описание:**
Цикл обновления данных аналоговых входов. Должна вызываться периодически (например, из основного цикла опроса). При каждом вызове выполняет:

1. **Получение сырых данных:** вызывает `modbus_poller_get_ai_raw()` для получения массива raw-значений (в микроамперах) из `CID_AI_REG_COUNT` Modbus-регистров. Phase-5: getter сам зануляет буфер на ошибочных путях, при `err_ai != ESP_OK` локально считаем устройство offline.
2. **Проверка онлайн-статуса:** `online = modbus_poller_is_device_online(MB_ADDR_WAVESHARE_AI) AND err_ai == ESP_OK`.
3. **Запись в кольцевой буфер:** записывает полученные raw-значения всех 8 каналов (мкА) в текущую позицию `s_ma_idx` буфера `s_ma_buf`, затем инкрементирует индекс (с оборотом по модулю `MA_WINDOW`). MA-буфер приватен для писателя и не требует синхронизации.
4. **Вычисление скользящего среднего:** для каждого активного канала (`enabled == true`) суммирует значения из буфера и делит на количество накопленных отсчётов (от 1 до `MA_WINDOW`). Результат `avg_uA` — усреднённое значение в микроамперах.
5. **Sensor-fault детекция (на оба конца):**
   - `fault_break = (avg_uA < FAULT_BREAK_UA)` — обрыв линии (ток < 3.5 мА);
   - `fault_short = (avg_uA > FAULT_SHORT_UA)` — короткое замыкание (ток > 20.5 мА);
   - `fault = fault_break OR fault_short`.
6. **Расчёт raw_ma (всегда, даже при fault):** `raw_ma = avg_uA / 1000.0f` — для диагностики.
7. **Преобразование в инженерные единицы:**
   - При `fault == true`: `value = NAN`, `valid = false`.
   - Иначе: `ratio = (avg_uA − UA_AT_4MA) / UA_SPAN`, клипуется в `[0.0, 1.0]` (нормальная зона датчика 3.5..20.5 мА укладывается с небольшим выходом за края, который прижимается к границам диапазона). `value = range_min + ratio * (range_max - range_min)`. `valid = online`.

Для неактивных каналов (`enabled == false`) устанавливается `valid = false, fault = false, value = 0, raw_ma = 0`.

Все вычисления производятся в локальной структуре `snapshot`; в самом конце snapshot атомарно копируется в `s_data` под spinlock'ом — читатели всегда видят целостный снимок.

**Параметры:** нет

**Возвращаемое значение:** нет (`void`)

## Алгоритм работы

### Скользящее среднее
Для подавления шума АЦП используется скользящее среднее с окном 8 отсчётов. Сырые значения (в мкА) записываются в кольцевой буфер `s_ma_buf`. При первых 7 вызовах `analog_input_update()` (до полного заполнения буфера) среднее вычисляется по фактически накопленным отсчётам. После полного заполнения — по всем 8 значениям в буфере.

### Преобразование raw → инженерные единицы

Модуль Waveshare AI 8CH (A) в режиме 3 (4–20 мА) возвращает сырые значения **напрямую в микроамперах**: 4 мА = 4000, 20 мА = 20000. Драйвер использует это свойство:

1. **Ток в мА:** `raw_ma = avg_uA / 1000.0f`.
2. **Нормализация:** `ratio = (avg_uA − UA_AT_4MA) / UA_SPAN = (avg_uA − 4000) / 16000`.
3. **Клиппинг:** ratio прижимается к `[0.0, 1.0]`. Это позволяет производственному допуску ±0.1 мА × 5 (зона 3.5..4.0 мА снизу и 20.0..20.5 мА сверху) укладываться без флага fault, но при этом не «улетать» за номинальный диапазон датчика.
4. **Линейная интерполяция:** `value = range_min + ratio * (range_max - range_min)`.

### Sensor-fault детекция (двусторонняя)

| Условие | Интерпретация |
|---------|---------------|
| `avg_uA < FAULT_BREAK_UA` (3500 мкА) | Обрыв токовой петли — нет «живого нуля» 4 мА. `value = NaN, valid = false`. |
| `avg_uA > FAULT_SHORT_UA` (20500 мкА) | Короткое замыкание / переходный процесс — ток выше допустимого максимума. `value = NaN, valid = false`. |
| `3500 ≤ avg_uA ≤ 20500` | Нормальный режим (с производственным допуском). `value` рассчитывается, `valid = device_online`. |

Раньше (до коммита `9a36029`) детектировался только обрыв (через порог `FAULT_RAW_THRESHOLD = 328` в неправильной 16-битной шкале); короткое замыкание не отлавливалось. Сейчас оба конца контролируются явно.

### Атомарная публикация снимка
Все вычисления производятся в локальной переменной `snapshot`. После расчётов snapshot копируется в `s_data` под spinlock'ом `s_data_mux` (`portENTER_CRITICAL` / `portEXIT_CRITICAL`). Читатели (`mqtt_task`, HTTP-сервер) забирают целостный снимок — без разрыва между значениями разных каналов.
