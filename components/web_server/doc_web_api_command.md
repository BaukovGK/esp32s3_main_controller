# web_api_command.c — POST-обработчики REST API команд и конфигурации

## Описание файла

Модуль `web_api_command` реализует все POST-обработчики REST API контроллера обратного осмоса. Через эти эндпоинты веб-интерфейс (или внешний клиент) может:

- Отправлять команды управления конечному автомату (старт, стоп, промывка, ручной режим, сброс аварий)
- Управлять дискретными выходами в ручном режиме
- Включать/выключать дозатор
- Изменять настройки давлений, дозатора, промывки, таймаутов и MQTT

Все запросы принимают тело в формате JSON и возвращают JSON-ответ `{"ok":true}` при успехе или `{"ok":false,"error":"..."}` при ошибке.

Модуль не имеет собственного заголовочного файла — его единственная публичная функция `web_api_register_commands()` объявлена как forward-declaration в `web_server.c`.

**Файл реализации:** `components/web_server/web_api_command.c`

## Константы и макросы

| Константа | Значение | Описание |
|-----------|----------|----------|
| `MAX_POST_SIZE` | `256` | Максимально допустимый размер тела POST-запроса в байтах. Запросы с телом больше этого размера отклоняются с ошибкой 400. Значение выбрано достаточным для всех JSON-команд и конфигурационных объектов. |

### `static cJSON *recv_json(httpd_req_t *req)`

**Область видимости:** внутренняя (static)

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `req` | `httpd_req_t *` | Указатель на структуру HTTP-запроса |

**Возвращаемое значение:**
- `cJSON *` — указатель на распарсенный JSON-объект, который вызывающий код обязан освободить через `cJSON_Delete()`
- `NULL` — если произошла ошибка (ответ с ошибкой уже отправлен клиенту)

**Описание:**

Универсальная функция приёма и парсинга JSON-тела POST-запроса:

1. Проверяет `content_len` запроса: должен быть > 0 и <= `MAX_POST_SIZE` (256). При нарушении — отправляет ошибку `"invalid body size"`.
2. Читает тело запроса в локальный буфер `buf[MAX_POST_SIZE + 1]` через `httpd_req_recv()`. При ошибке чтения — отправляет `"recv failed"`.
3. Добавляет нулевой терминатор.
4. Парсит JSON через `cJSON_Parse()`. При ошибке парсинга — отправляет `"invalid JSON"`.
5. Возвращает указатель на корневой cJSON-объект.

### `static esp_err_t command_post_handler(httpd_req_t *req)`

**Область видимости:** внутренняя (static)
**URI:** `POST /api/v1/command`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `req` | `httpd_req_t *` | Указатель на структуру HTTP-запроса |

**Возвращаемое значение:** `ESP_OK`

**Ожидаемое тело запроса (JSON):**
```json
{"cmd": "<строка_команды>"}
```

**Поддерживаемые команды:**

| Строка | Константа `sm_command_t` | Описание |
|--------|--------------------------|----------|
| `"start_auto"` | `CMD_START_AUTO` | Запуск автоматического режима |
| `"stop"` | `CMD_STOP` | Остановка процесса |
| `"start_washing"` | `CMD_START_WASHING` | Запуск режима промывки |
| `"set_manual"` | `CMD_SET_MANUAL` | Переход в ручной режим |
| `"reset_fault"` | `CMD_RESET_FAULT` | Сброс аварий |

**Описание:**

Обработчик команд управления конечным автоматом:

1. Принимает и парсит JSON через `recv_json()`.
2. Извлекает строковое поле `"cmd"`. Если отсутствует или не строка — ошибка 400.
3. Преобразует строку команды в перечисление `sm_command_t` через цепочку `strcmp()`.
4. При неизвестной команде — ошибка 400 `"unknown command"`.
5. Вызывает `state_machine_send_command(cmd)` для передачи команды конечному автомату.
6. Логирует принятую команду и возвращает `{"ok":true}`.

### `static esp_err_t manual_do_post_handler(httpd_req_t *req)`

**Область видимости:** внутренняя (static)
**URI:** `POST /api/v1/manual/do`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `req` | `httpd_req_t *` | Указатель на структуру HTTP-запроса |

**Возвращаемое значение:** `ESP_OK`

**Ожидаемое тело запроса (JSON):**
```json
{"mask": <число 0-255>}
```

**Описание:**

Обработчик ручного управления дискретными выходами (DO):

1. **Проверка режима:** Если текущее состояние конечного автомата не `SM_MANUAL` — возвращает ошибку 409 `"not in MANUAL mode"`.
2. Принимает и парсит JSON.
3. Извлекает числовое поле `"mask"`. Если отсутствует или не число — ошибка 400.
4. Приводит значение к `uint8_t` (битовая маска выходов).
5. Вызывает `state_machine_manual_set_do(mask)` для установки дискретных выходов.
6. Логирует маску в шестнадцатеричном формате.

### `static esp_err_t config_pressure_post_handler(httpd_req_t *req)`

**Область видимости:** внутренняя (static)
**URI:** `POST /api/v1/config/pressure`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `req` | `httpd_req_t *` | Указатель на структуру HTTP-запроса |

**Возвращаемое значение:** `ESP_OK`

**Ожидаемое тело запроса (JSON):**
```json
{
  "p1_max": <float>,
  "p3_max": <float>,
  "p4_max": <float>,
  "filter_dp_warn": <float>
}
```

Все поля необязательны — обновляются только переданные.

**Описание:**

Обработчик обновления конфигурации давлений:

1. Принимает и парсит JSON.
2. Получает текущую конфигурацию давлений через `config_manager_get()->pressure`.
3. Для каждого переданного числового поля обновляет соответствующее значение в локальной копии:
   - `p1_max` — максимальное давление P1 (бар)
   - `p3_max` — максимальное давление P3 (бар)
   - `p4_max` — максимальное давление P4 (бар)
   - `filter_dp_warn` — порог предупреждения по перепаду давления на фильтре (бар)
4. Сохраняет конфигурацию через `config_manager_set_pressure(&cfg)`.

### `static esp_err_t config_mqtt_post_handler(httpd_req_t *req)`

**Область видимости:** внутренняя (static)
**URI:** `POST /api/v1/config/mqtt`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `req` | `httpd_req_t *` | Указатель на структуру HTTP-запроса |

**Возвращаемое значение:** `ESP_OK`

**Ожидаемое тело запроса (JSON):**
```json
{
  "broker_uri": "<строка>",
  "username": "<строка>",
  "password": "<строка>",
  "client_id": "<строка>",
  "publish_interval_s": <int>,
  "enabled": <int 0|1>
}
```

Все поля необязательны.

**Описание:**

Обработчик обновления конфигурации MQTT:

1. Принимает и парсит JSON.
2. Получает текущую конфигурацию MQTT.
3. Обновляет переданные поля:
   - `broker_uri` — URI MQTT-брокера (копируется с защитой от переполнения через `strncpy`)
   - `username` — имя пользователя MQTT (копируется с защитой от переполнения)
   - `password` — пароль MQTT (копируется с защитой от переполнения)
   - `client_id` — идентификатор клиента MQTT (копируется с защитой от переполнения)
   - `publish_interval_s` — интервал публикации телеметрии (секунды)
   - `enabled` — флаг включения MQTT (0 или 1)
4. Сохраняет через `config_manager_set_mqtt(&cfg)`.
5. Логирует обновлённый URI брокера.
6. **Управляет MQTT-клиентом:**
   - Если `enabled` = true — вызывает `mqtt_app_reconnect()` для переподключения с новыми параметрами.
   - Если `enabled` = false — вызывает `mqtt_app_stop()` для остановки MQTT.

## Архитектурные замечания

- Все конфигурационные обработчики используют паттерн «read-modify-write»: сначала считывают текущую конфигурацию, затем обновляют только переданные поля, затем сохраняют целиком. Это позволяет клиенту обновлять отдельные параметры, не передавая всю структуру целиком.
- Буфер приёма POST-тела (`MAX_POST_SIZE = 256`) выделяется на стеке, что эффективно для ESP32, но ограничивает размер запроса.
- Обработчик MQTT-конфигурации дополнительно управляет жизненным циклом MQTT-клиента, что связывает модуль конфигурации с модулем MQTT.
- Строковые поля MQTT-конфигурации копируются с защитой от переполнения (`strncpy` + принудительный нулевой терминатор).
