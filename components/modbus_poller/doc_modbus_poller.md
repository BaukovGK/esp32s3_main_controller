# modbus_poller.h / modbus_poller.c — Modbus RTU Master: менеджер циклического опроса

## Описание файла

Модуль `modbus_poller` реализует Modbus RTU Master для циклического опроса подчинённых устройств контроллера обратного осмоса по шине RS-485. Модуль:

- Инициализирует стек esp-modbus v2 в режиме Serial RTU Master
- Определяет Data Dictionary (набор параметров) для всех опрашиваемых устройств
- Выполняет циклический опрос устройств с индивидуальными периодами
- Хранит сырые данные регистров в потокобезопасных буферах
- Предоставляет getter-функции для доступа к данным из других задач
- Отслеживает ошибки связи и определяет статус online/offline устройств

**Заголовочный файл:** `components/modbus_poller/include/modbus_poller.h`
**Файл реализации:** `components/modbus_poller/modbus_poller.c`

## Функции

### `esp_err_t modbus_poller_init(void)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:** нет

**Возвращаемое значение:**
- `ESP_OK` — Modbus Master инициализирован успешно
- `ESP_ERR_NO_MEM` — не удалось создать мьютекс
- Код ошибки esp-modbus — при ошибке на любом этапе

**Описание:**

Выполняет полную инициализацию Modbus RTU Master:

1. **Создание мьютекса** (`xSemaphoreCreateMutex()`) для защиты буферов данных.
2. **Создание Serial Master** через `mbc_master_create_serial()` с параметрами:
   - Режим RTU
   - UART-порт из `BOARD_RS485_UART_PORT`
   - Таймаут ответа `MB_RESPONSE_TIMEOUT_MS` (300 мс, Phase-1 — было 1000)
   - Скорость из `BOARD_RS485_BAUDRATE`
   - 8 бит данных, 1 стоп-бит, без контроля чётности
3. **Настройка GPIO UART** через `uart_set_pin()` (TX, RX, RTS из board_config).
4. **Регистрация Data Dictionary** через `mbc_master_set_descriptor()` с массивом `s_device_params`.
5. **Настройка режима RS-485** полудуплекс через `uart_set_mode(UART_MODE_RS485_HALF_DUPLEX)`.
6. **Запуск стека** через `mbc_master_start()`.
7. Логирует количество CID, номер UART и скорость.

При ошибке на любом этапе логирует её и возвращает код ошибки.

### `void modbus_poller_task(void *arg)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `arg` | `void *` | Не используется (стандартная сигнатура задачи FreeRTOS) |

**Возвращаемое значение:** нет (бесконечный цикл, задача никогда не завершается)

**Описание:**

FreeRTOS-задача циклического опроса Modbus-устройств:

1. **Watchdog handle** извлекается из `arg` (encoding `+1` через `WDT_ARG_TO_HANDLE`, см. `watchdog_task.h`). Phase-1 (K-5).
2. **Начальная задержка** `MB_BUS_INIT_DELAY_MS` (500 мс) для стабилизации шины RS-485 после инициализации.
3. **Основной цикл** (бесконечный):
   - Получает текущее время в миллисекундах через `esp_timer_get_time()/1000`.
   - Итерирует по таблице опроса `s_poll_table`.
   - **Phase-2 (H-9):** для каждой записи определяет рабочий период: если `error_count >= DEVICE_OFFLINE_THRESHOLD`, период увеличивается до `MB_OFFLINE_BACKOFF_MS` (30 сек), иначе используется штатный `entry->period_ms`.
   - Если период истёк — выполняет чтение:
     - Готовит временный буфер размером `CID_KWS_REG_COUNT * 2 = 28 байт` (раньше было 16 байт = `CID_FLOW_VOL_REG_COUNT_OLD * 2`; увеличен потому что KWS теперь самый большой блок — 14 регистров).
     - Вызывает `mbc_master_get_parameter()` с CID записи и временным буфером.
     - Захватывает мьютекс через `data_lock("poll")` с таймаутом `MB_DATA_LOCK_TIMEOUT_MS` (100 мс).
     - При успехе: конвертирует данные из массива байт (big-endian Modbus) в массив `uint16_t` и копирует в буфер данных. Сбрасывает счётчик ошибок. Если ранее были ошибки — логирует восстановление связи. Phase-5: при первом успешном опросе устанавливает `first_poll_done = true` и логирует это событие.
     - При ошибке: инкрементирует счётчик ошибок. Логирует первую ошибку и момент достижения порога `DEVICE_OFFLINE_THRESHOLD`.
     - Освобождает мьютекс.
   - Обновляет `last_poll_ms`.
   - **Phase-1 (K-5):** кормит watchdog через `watchdog_feed_h(s_wdt_handle)`, если handle получен.
   - Задержка `MB_POLL_TASK_INTERVAL_MS` (10 мс) (`vTaskDelay`) для предотвращения голодания других задач.

**Конвертация данных:**
Esp-modbus v2 возвращает данные как массив байт. Функция конвертирует их в uint16_t с учётом порядка байт Modbus (big-endian): `data_buf[r] = (temp_buf[r*2] << 8) | temp_buf[r*2 + 1]`.

### `static esp_err_t get_raw_data_by_cid(modbus_cid_t cid, uint16_t *out, size_t out_count)`

**Область видимости:** внутренняя (static)

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `cid` | `modbus_cid_t` | Идентификатор набора регистров |
| `out` | `uint16_t *` | Указатель на выходной буфер, предоставленный вызывающим |
| `out_count` | `size_t` | Размер выходного буфера в uint16_t элементах |

**Возвращаемое значение:**
- `ESP_OK` — данные скопированы
- `ESP_ERR_NOT_FOUND` — CID не найден в таблице
- `ESP_ERR_INVALID_SIZE` — `out == NULL` или буфер слишком мал
- `ESP_ERR_TIMEOUT` — не удалось взять лок данных за `MB_GETTER_LOCK_TIMEOUT_MS` (50 мс)
- `ESP_ERR_INVALID_STATE` — до сих пор не было ни одного успешного опроса (`first_poll_done == false`)

**Описание:**

Вспомогательная потокобезопасная функция копирования данных из внутреннего буфера во внешний. Phase-5 (C-9, C-10, H-modbus-initial-state):

1. **Пред-обнуление out:** `memset(out, 0, ...)` ДО любых проверок состояния — caller никогда не получает мусор.
2. **Короткий таймаут лока** `MB_GETTER_LOCK_TIMEOUT_MS` (50 мс) — readers не висят при зависании poll task'а.
3. **Проверка `first_poll_done`:** пока не было первого УСПЕШНОГО ответа, возвращает `ESP_ERR_INVALID_STATE`. Caller не должен трактовать стартовые нули как валидные данные.
4. **Атомарное копирование** через `memcpy()` под локом, затем `data_unlock()`.

### `bool modbus_poller_is_device_online(uint8_t slave_addr)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `slave_addr` | `uint8_t` | Modbus-адрес проверяемого устройства |

**Возвращаемое значение:**
- `true` — устройство считается доступным (количество последовательных ошибок < `DEVICE_OFFLINE_THRESHOLD`)
- `false` — устройство offline или не найдено в таблице опроса

**Описание:**

Проверяет доступность Modbus-устройства по его адресу:

1. **Phase-5 (C-9, C-10):** захватывает лок с таймаутом `MB_GETTER_LOCK_TIMEOUT_MS` (50 мс). На таймаут — возвращает `false` (по умолчанию небезопасно считать устройство online).
2. Проходит по всей таблице опроса `s_poll_table`.
3. Находит все записи с указанным `slave_addr` (одно устройство может иметь несколько CID).
4. Среди записей с `first_poll_done == true` определяет максимальный `error_count`.
5. **Phase-5 (H-modbus-initial-state):** если устройство не найдено в таблице, ИЛИ ни по одной из его записей не было первого успешного опроса (`any_polled == false`) — возвращает `false`. Иначе caller примет стартовые нули за «всё в порядке».
6. Возвращает `true`, если максимальное количество ошибок меньше `DEVICE_OFFLINE_THRESHOLD` (10).

### `uint32_t modbus_poller_get_error_count(uint8_t slave_addr)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `slave_addr` | `uint8_t` | Modbus-адрес устройства |

**Возвращаемое значение:** Максимальное количество последовательных ошибок для данного устройства (0 = нет ошибок). Если устройство не найдено — возвращает 0.

**Описание:**

Возвращает количество последовательных ошибок связи с устройством. Логика аналогична `modbus_poller_is_device_online()`:

## Архитектурные замечания

- **Потокобезопасность:** Все буферы данных защищены мьютексом `s_data_mutex`. Phase-1/Phase-5: писатель (`modbus_poller_task`) использует таймаут `MB_DATA_LOCK_TIMEOUT_MS` (100 мс) с алярмом `ALARM_MB_DATA_LOCK_HUNG`, читатели (геттеры) — короткий `MB_GETTER_LOCK_TIMEOUT_MS` (50 мс) без алярма.
- **Индивидуальные периоды опроса:** Аналоговые входы опрашиваются чаще всего (`MB_POLL_PERIOD_AI_MS` = 100 мс), расход — `MB_POLL_PERIOD_FLOW_MS` (1 с), объём и счётчики KWS — 2 с (`MB_POLL_PERIOD_VOL_MS`, `MB_POLL_PERIOD_KWS_MS`), кондуктометры — `MB_POLL_PERIOD_COND_MS` (3 с). Это отражает различную скорость изменения измеряемых величин.
- **Обработка ошибок:** Логирование ошибок оптимизировано — логируется только первая ошибка и момент перехода в offline. Восстановление связи также логируется.
- **Phase-5 (H-modbus-initial-state):** до первого успешного опроса любой записи геттеры возвращают `ESP_ERR_INVALID_STATE`, а `is_device_online()` — `false`. Caller не должен трактовать стартовые нули как валидные данные.
- **Phase-2 (H-9):** offline-устройства (>= 10 ошибок подряд) опрашиваются с увеличенным периодом `MB_OFFLINE_BACKOFF_MS` (30 сек), чтобы не блокировать шину RS-485 на каждом цикле poll'а.
- **Big-endian конвертация:** Modbus использует big-endian порядок байт, данные конвертируются в uint16_t при сохранении в буфер.
- **Временный буфер:** Для чтения используется временный буфер максимального размера. Сейчас максимум — `CID_KWS_REG_COUNT * 2 = 28` байт (раньше было 16 байт по `CID_FLOW_VOL_REG_COUNT_OLD * 2`). Выделяется на стеке. Если будет добавлен CID > 14 регистров — увеличить размер.
- **Watchdog (Phase-1, K-5):** задача `modbus_poller_task` подключается к watchdog'у через handle, переданный в `arg` (encoding `+1` через `WDT_HANDLE_TO_ARG`). На каждой итерации цикла вызывается `watchdog_feed_h()`.
- **Модуль не является самостоятельной задачей** — функция `modbus_poller_task()` должна быть запущена как задача FreeRTOS из `app_main`.
