# modbus_poller.h / modbus_poller.c — Modbus RTU Master: менеджер циклического опроса

## Описание файла

Модуль `modbus_poller` реализует Modbus RTU Master для циклического опроса подчинённых устройств контроллера обратного осмоса по шине RS-485. Модуль:

- Инициализирует стек esp-modbus v2 в режиме Serial RTU Master
- Определяет Data Dictionary (набор параметров) для всех опрашиваемых устройств
- Выполняет циклический опрос устройств с индивидуальными периодами
- Хранит сырые данные регистров в потокобезопасных буферах
- Предоставляет getter-функции для доступа к данным из других задач
- Отслеживает ошибки связи и определяет статус online/offline устройств

**Заголовочный файл:** `components/modbus_poller/include/modbus_poller.h`
**Файл реализации:** `components/modbus_poller/modbus_poller.c`

## Функции

### `esp_err_t modbus_poller_init(void)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:** нет

**Возвращаемое значение:**
- `ESP_OK` — Modbus Master инициализирован успешно
- `ESP_ERR_NO_MEM` — не удалось создать мьютекс
- Код ошибки esp-modbus — при ошибке на любом этапе

**Описание:**

Выполняет полную инициализацию Modbus RTU Master:

1. **Создание мьютекса** (`xSemaphoreCreateMutex()`) для защиты буферов данных.
2. **Создание Serial Master** через `mbc_master_create_serial()` с параметрами:
   - Режим RTU
   - UART-порт из `BOARD_RS485_UART_PORT`
   - Таймаут ответа `MB_RESPONSE_TIMEOUT_MS` (1000 мс)
   - Скорость из `BOARD_RS485_BAUDRATE`
   - 8 бит данных, 1 стоп-бит, без контроля чётности
3. **Настройка GPIO UART** через `uart_set_pin()` (TX, RX, RTS из board_config).
4. **Регистрация Data Dictionary** через `mbc_master_set_descriptor()` с массивом `s_device_params`.
5. **Настройка режима RS-485** полудуплекс через `uart_set_mode(UART_MODE_RS485_HALF_DUPLEX)`.
6. **Запуск стека** через `mbc_master_start()`.
7. Логирует количество CID, номер UART и скорость.

При ошибке на любом этапе логирует её и возвращает код ошибки.

### `void modbus_poller_task(void *arg)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `arg` | `void *` | Не используется (стандартная сигнатура задачи FreeRTOS) |

**Возвращаемое значение:** нет (бесконечный цикл, задача никогда не завершается)

**Описание:**

FreeRTOS-задача циклического опроса Modbus-устройств:

1. **Начальная задержка** `MB_BUS_INIT_DELAY_MS` (500 мс) для стабилизации шины RS-485 после инициализации.
2. **Основной цикл** (бесконечный):
   - Получает текущее время в миллисекундах.
   - Итерирует по таблице опроса `s_poll_table`.
   - Для каждой записи проверяет, прошёл ли период с последнего опроса.
   - Если период истёк — выполняет чтение:
     - Вызывает `mbc_master_get_parameter()` с CID записи и временным буфером.
     - Захватывает мьютекс (`xSemaphoreTake`).
     - При успехе: конвертирует данные из массива байт (big-endian Modbus) в массив `uint16_t` и копирует в буфер данных. Сбрасывает счётчик ошибок. Если ранее были ошибки — логирует восстановление связи.
     - При ошибке: инкрементирует счётчик ошибок. Логирует первую ошибку и момент достижения порога `DEVICE_OFFLINE_THRESHOLD`.
     - Освобождает мьютекс.
   - Обновляет `last_poll_ms`.
   - Задержка `MB_POLL_TASK_INTERVAL_MS` (10 мс) (`vTaskDelay`) для предотвращения голодания других задач.

**Конвертация данных:**
Esp-modbus v2 возвращает данные как массив байт. Функция конвертирует их в uint16_t с учётом порядка байт Modbus (big-endian): `data_buf[r] = (temp_buf[r*2] << 8) | temp_buf[r*2 + 1]`.

### `bool modbus_poller_is_device_online(uint8_t slave_addr)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `slave_addr` | `uint8_t` | Modbus-адрес проверяемого устройства |

**Возвращаемое значение:**
- `true` — устройство считается доступным (количество последовательных ошибок < `DEVICE_OFFLINE_THRESHOLD`)
- `false` — устройство offline или не найдено в таблице опроса

**Описание:**

Проверяет доступность Modbus-устройства по его адресу:

1. Проходит по всей таблице опроса `s_poll_table`.
2. Находит все записи с указанным `slave_addr` (одно устройство может иметь несколько CID).
3. Определяет максимальный `error_count` среди всех записей устройства.
4. Если устройство не найдено — возвращает `false`.
5. Возвращает `true`, если максимальное количество ошибок меньше `DEVICE_OFFLINE_THRESHOLD` (10).

---

### `uint32_t modbus_poller_get_error_count(uint8_t slave_addr)`

**Объявлена в:** `modbus_poller.h`
**Реализована в:** `modbus_poller.c`

**Параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `slave_addr` | `uint8_t` | Modbus-адрес устройства |

**Возвращаемое значение:** Максимальное количество последовательных ошибок для данного устройства (0 = нет ошибок). Если устройство не найдено — возвращает 0.

**Описание:**

Возвращает количество последовательных ошибок связи с устройством. Логика аналогична `modbus_poller_is_device_online()` — находит максимальный `error_count` среди всех CID данного устройства.

## Архитектурные замечания

- **Потокобезопасность:** Все буферы данных защищены мьютексом `s_data_mutex`. Задача опроса захватывает мьютекс при записи, getter-функции — при чтении.
- **Индивидуальные периоды опроса:** Аналоговые входы опрашиваются чаще всего (`MB_POLL_PERIOD_AI_MS` = 100 мс), расход — `MB_POLL_PERIOD_FLOW_MS` (1 с), объём — `MB_POLL_PERIOD_VOL_MS` (2 с), кондуктометры — `MB_POLL_PERIOD_COND_MS` (3 с). Это отражает различную скорость изменения измеряемых величин.
- **Обработка ошибок:** Логирование ошибок оптимизировано — логируется только первая ошибка и момент перехода в offline. Восстановление связи также логируется.
- **Big-endian конвертация:** Modbus использует big-endian порядок байт, данные конвертируются в uint16_t при сохранении в буфер.
- **Временный буфер:** Для чтения используется временный буфер максимального размера (`CID_FLOW_VOL_REG_COUNT * 2 = 32` байта), выделенный на стеке.
- **Модуль не является самостоятельной задачей** — функция `modbus_poller_task()` должна быть запущена как задача FreeRTOS из `app_main`.
