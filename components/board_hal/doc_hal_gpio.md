# hal_gpio.h / hal_gpio.c -- Дискретные входы (DI) и релейные выходы (DO)

## Описание модуля

Модуль аппаратной абстракции для работы с дискретными входами (DI1-DI8) и релейными выходами (RO1-RO8) платы Waveshare ESP32-S3-ETH-8DI-8RO.

**Дискретные входы (DI1-DI8):** подключены к прямым GPIO микроконтроллера через оптоизоляторы. Логика **инвертирована**: LOW на GPIO означает "вход активен" (замкнут на GND). Реализован программный debounce (антидребезг) с порогом 50 мс (5 вызовов по 10 мс).

**Релейные выходы (RO1-RO8):** управляются через I2C-расширитель портов TCA9554PWR по адресу 0x20. Текущее состояние выходов кэшируется в оперативной памяти. При ошибке записи I2C выполняется одна автоматическая повторная попытка.

**Phase-1 (отказоустойчивость):**
- **K-3 (DEADLOCK fix):** ранее RMW-доступ к `s_do_state` защищался `portMUX_TYPE` (spinlock) — внутри critical section вызывался `hal_i2c_write_reg`, который сам блокировался на семафоре. ESP-IDF категорически запрещает блокирующие вызовы в critical section → возможный deadlock/assert. Заменено на FreeRTOS `SemaphoreHandle_t` с таймаутом 100 мс.
- **K-2 (TCA9554 readback):** добавлена функция `hal_gpio_verify_do()` — читает регистр OUTPUT TCA9554 и сравнивает с кэшем `s_do_state`. Вызывается раз в секунду из `process_task`. При расхождении возвращает `ESP_ERR_INVALID_STATE` (caller поднимает `ALARM_DO_READBACK_FAIL`) и пытается восстановить состояние повторной записью.
- **K-2 (init verify):** после первой записи 0x00 в OUTPUT/CONFIG `hal_gpio_init()` читает OUTPUT обратно и проверяет совпадение. Если TCA9554 не отвечает или отвечает мусором — init возвращает ошибку.

**Файлы:**
- Заголовок: `components/board_hal/include/hal_gpio.h`
- Реализация: `components/board_hal/hal_gpio.c`

#### Регистры TCA9554PWR

| Константа | Значение | Описание |
|---|---|---|
| `TCA9554_REG_INPUT` | `0x00` | Адрес регистра чтения входных данных TCA9554 |
| `TCA9554_REG_OUTPUT` | `0x01` | Адрес регистра записи выходных данных TCA9554. Запись в этот регистр устанавливает состояние выходных пинов |

| `TCA9554_REG_CONFIG` | `0x03` | Адрес регистра конфигурации направления пинов TCA9554. 0 = выход, 1 = вход |

#### Параметры debounce

| Константа | Значение | Описание |
|---|---|---|
| `DEBOUNCE_THRESHOLD` | `5` | Количество последовательных одинаковых считываний для фиксации нового состояния. При вызове каждые 10 мс даёт порог 50 мс |

## Функции

### hal_gpio_init

```c
esp_err_t hal_gpio_init(void);
```

**Описание:** Инициализация подсистемы дискретного ввода-вывода. Выполняет две основные задачи:

1. **Настройка DI (GPIO):** Для каждого из 8 дискретных входов конфигурирует соответствующий GPIO как вход с внутренней подтяжкой к питанию (pull-up), без прерываний. Подтяжка необходима, так как оптоизоляторы при активации замыкают линию на GND.

2. **Настройка DO (TCA9554):** Записывает 0x00 в регистр выходов TCA9554 (все реле выключены), затем записывает 0x00 в регистр конфигурации (все пины настроены как выходы).

3. **Инициализация debounce:** Обнуляет массив счётчиков `s_debounce_cnt` и переменную `s_di_stable`.

**Параметры:** Нет.

**Возвращаемое значение:**
- `ESP_OK` -- успешная инициализация
- Код ошибки ESP-IDF -- при ошибке конфигурации GPIO или при отсутствии ответа от TCA9554 по I2C

**Предусловия:** Необходим предварительный вызов `hal_i2c_init()`.

---

### hal_gpio_debounce_process

```c
void hal_gpio_debounce_process(void);
```

**Описание:** Процедура программного антидребезга (debounce) для всех дискретных входов. Должна вызываться периодически (каждые 10 мс) из задачи ввода-вывода (IoTask).

**Алгоритм работы (для каждого DI):**
1. Считывает текущий уровень GPIO. Инвертирует значение: LOW (0) = активен (`true`), HIGH (1) = неактивен (`false`).
2. Сравнивает с текущим стабилизированным состоянием из `s_di_stable`.
3. Если состояние отличается -- инкрементирует счётчик `s_debounce_cnt[i]`.
4. Если счётчик достиг порога `DEBOUNCE_THRESHOLD` (5) -- обновляет бит в `s_di_stable` и сбрасывает счётчик.
5. Если состояние совпадает со стабилизированным -- сбрасывает счётчик в 0.

**Параметры:** Нет.

**Возвращаемое значение:** Нет (`void`).

---

### hal_gpio_read_di

```c
uint8_t hal_gpio_read_di(void);
```

**Описание:** Возвращает стабилизированное (после debounce) состояние всех 8 дискретных входов в виде битовой маски.

**Параметры:** Нет.

**Возвращаемое значение:** `uint8_t` -- битовая маска состояния DI:
- Бит 0 (0x01) = DI1
- Бит 1 (0x02) = DI2
- ...
- Бит 7 (0x80) = DI8
- Значение бита: 1 = вход активен (замкнут на GND), 0 = неактивен

---

### hal_gpio_read_di_pin

```c
bool hal_gpio_read_di_pin(uint8_t pin);
```

**Описание:** Возвращает стабилизированное (после debounce) состояние одного дискретного входа.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `pin` | `uint8_t` | Номер дискретного входа. Допустимые значения: 1..8 (1 = DI1, 8 = DI8) |

**Возвращаемое значение:** `bool`:
- `true` -- вход активен (замкнут на GND)
- `false` -- вход неактивен, либо указан недопустимый номер пина (< 1 или > 8)

### hal_gpio_write_do

```c
esp_err_t hal_gpio_write_do(uint8_t mask);
```

**Описание:** Устанавливает состояние всех 8 релейных выходов одновременно. Записывает байт маски в регистр выходов TCA9554 по I2C. При ошибке записи выполняет одну автоматическую повторную попытку. При успешной записи обновляет внутренний кэш `s_do_state`.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `mask` | `uint8_t` | Битовая маска состояния выходов. Бит 0 = RO1, бит 7 = RO8. 1 = включить реле, 0 = выключить |

**Возвращаемое значение:**
- `ESP_OK` -- успешная запись (в том числе при успехе повторной попытки)
- Код ошибки ESP-IDF -- при неудаче обеих попыток записи

---

### hal_gpio_write_do_pin

```c
esp_err_t hal_gpio_write_do_pin(uint8_t pin, bool state);
```

**Описание:** Устанавливает состояние одного релейного выхода, не затрагивая остальные. Внутри модифицирует кэшированное значение `s_do_state` и вызывает `hal_gpio_write_do()`.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `pin` | `uint8_t` | Номер выхода. Допустимые значения: 1..8 (1 = RO1, 8 = RO8) |
| `state` | `bool` | `true` = включить реле, `false` = выключить |

**Возвращаемое значение:**
- `ESP_OK` -- успешная запись
- `ESP_ERR_INVALID_ARG` -- недопустимый номер пина (< 1 или > 8)
- Код ошибки ESP-IDF -- при ошибке записи I2C

---

### hal_gpio_read_do_state

```c
uint8_t hal_gpio_read_do_state(void);
```

**Описание:** Возвращает текущее кэшированное состояние дискретных выходов. Значение берётся из внутренней переменной `s_do_state`, а не считывается из TCA9554 по I2C.

**Параметры:** Нет.

**Возвращаемое значение:** `uint8_t` -- битовая маска текущего состояния выходов:
- Бит 0 (0x01) = RO1
- Бит 7 (0x80) = RO8
- 1 = реле включено, 0 = выключено

---

### hal_gpio_verify_do  *(Phase-1, K-2)*

```c
esp_err_t hal_gpio_verify_do(void);
```

**Описание:** Контрольное чтение регистра OUTPUT TCA9554 и сравнение с кэшированным состоянием `s_do_state`.

Вызывается раз в секунду из `process_task` (10 циклов по 100 мс). При несовпадении пытается восстановить состояние повторной записью ожидаемого значения.

**Параметры:** Нет.

**Возвращаемое значение:**
- `ESP_OK` — реальное состояние совпало с ожидаемым
- `ESP_ERR_INVALID_STATE` — расхождение (caller должен поднять `ALARM_DO_READBACK_FAIL`)
- Иной — ошибка чтения I2C (caller должен поднять `ALARM_I2C_BUS_HUNG`)

**Важно:** функция сама **не вызывает** `alarm_raise` — это нарушило бы слоистую архитектуру (`board_hal` не должен зависеть от `services`). Алармы поднимает `process_task` по возвращаемому коду.

---

### hal_gpio_is_estop_raw

```c
bool hal_gpio_is_estop_raw(void);
```

**Описание:** Мгновенное чтение состояния кнопки аварийного останова (E-STOP, DI5) **без debounce**. Читает GPIO напрямую через `gpio_get_level()`, минуя систему антидребезга. Предназначена для обеспечения минимального времени реакции на аварийный сигнал (менее 10 мс).

Вход DI5 подключён к GPIO 8 (`BOARD_DI5_GPIO`). Логика инвертирована: LOW (0) на GPIO = E-STOP активен.

**Параметры:** Нет.

**Возвращаемое значение:** `bool`:
- `true` -- аварийный стоп активен (DI5 замкнут на GND)
- `false` -- аварийный стоп не активен

## Примечания

- Нумерация входов и выходов в API **начинается с 1** (DI1, RO1), а не с 0. Внутри реализации происходит преобразование `pin - 1` для доступа к массивам и битам.
- Debounce реализован без использования прерываний -- только опросом (polling). Это упрощает код и гарантирует детерминированное поведение.
- При ошибке I2C-записи в `hal_gpio_write_do()` выполняется ровно одна повторная попытка. Если и она не удалась, возвращается код ошибки, но внутренний кэш `s_do_state` **не обновляется** (сохраняет последнее успешно записанное значение). При следующем `hal_gpio_verify_do()` будет обнаружено расхождение → `ALARM_DO_READBACK_FAIL`.
- Функция `hal_gpio_is_estop_raw()` обращается к GPIO напрямую (без debounce) для обеспечения быстрой реакции на аварию. В штатном режиме состояние E-STOP можно также получить через `hal_gpio_read_di_pin(5)`, но с задержкой до 50 мс.
- **Phase-1**: HAL не зависит от `alarm_manager` — алармы поднимаются вызывающим слоем по возвращаемым кодам (`ESP_ERR_TIMEOUT`, `ESP_ERR_INVALID_STATE`). Это сохраняет однонаправленную зависимость `services → board_hal` без циклов.
