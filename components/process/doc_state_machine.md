# state_machine.h / state_machine.c

## Описание модуля

Модуль реализует **конечный автомат (КА)** управления установкой обратного осмоса. Является центральным управляющим модулем системы: принимает команды от оператора (HMI/MQTT), управляет насосами, ТЭНом, контролирует последовательность пуска/останова, реализует алгоритм химической промывки мембран.

**Файлы:**
- `components/process/include/state_machine.h` -- публичный заголовок (перечисления, структуры, API)
- `components/process/state_machine.c` -- реализация КА

**Частота вызова:** функция `state_machine_update()` вызывается каждые 100 мс из `process_task`.

## Phase-2 (K-4): Persistence SM-state в NVS

При каждом переходе между состояниями (через `set_state()`) и при каждом подъёме `enter_fault()` функция `persist_sm_state()` записывает в NVS два ключа:

| NVS-ключ | Тип | Содержимое |
|---|---|---|
| `sm_state` | `int32` | Текущее `sm_state_t` (0=IDLE, 1=AUTO, 2=WASHING, 3=MANUAL, 4=FAULT) |
| `sm_fault` | `int32` | Битовая маска `s_fault_flags` (комбинация `INTERLOCK_*`) |

При старте `state_machine_init()` читает эти ключи и принимает решение:

| Сохранённое состояние | Поведение init |
|---|---|
| `SM_FAULT` | Восстанавливаем FAULT с теми же flags. Оператор должен сделать `CMD_RESET_FAULT`. |
| `SM_AUTO` или `SM_WASHING` | **Считаем перезагрузку аварийной** (panic / WDT / brownout). Входим в FAULT с `INTERLOCK_UNEXPECTED_RESTART` + поднимаем `ALARM_RESTART_DURING_OP`. Слепо продолжать работу нельзя — фактическое состояние агрегатов после рестарта неизвестно. |
| `SM_IDLE` / `SM_MANUAL` / отсутствует / повреждено | Чистый старт с `SM_IDLE`, fault_flags=0. |

**До Phase-2** `state_machine_init()` всегда стартовал с IDLE — после watchdog-restart во время WASHING причина FAULT терялась, оператор не видел истории, а опасные сценарии (рестарт с горячим ТЭНом) обрабатывались только аппаратными интерлоками.

## Phase-4 (C-2): Атомарность `s_wash_confirm_pending`

Флаг подтверждения фазы промывки оператором пишется не из ProcessTask (httpd-обработчик `/api/v1/wash/confirm` или MQTT-подписчик вызывают `state_machine_send_command(CMD_CONFIRM_WASH_PHASE)`, после чего в `state_machine_update` под спинлоком команда читается и **затем без синхронизации** устанавливался `s_wash_confirm_pending = true`). Чтение в `update_washing` тоже было без синхронизации:

```c
bool confirmed = s_wash_confirm_pending;  // race
s_wash_confirm_pending = false;            // race
```

Хотя `bool`/`uint8` атомарен на ESP32-S3 при выровненном доступе, формально это data race (UB по C11). Заменено на `_Atomic bool` + `atomic_store`/`atomic_exchange`. `atomic_exchange` гарантирует, что флаг, выставленный между чтением и сбросом, не теряется.

## Phase-4 (C-3): Валидация SM-state из NVS

В Phase-2 при восстановлении из NVS значения `int32_t` напрямую приводились к `sm_state_t` и `uint32_t fault_flags`. Если NVS повреждена (износ flash, прерванная запись, чужие данные), это давало:

- Невалидное `sm_state_t` (например, 99) → UB при последующих сравнениях.
- Биты `fault_flags` вне известной маски → оператор видит «фейковые» аварии.

Теперь:

1. Проверяется диапазон `saved_state ∈ [SM_IDLE, SM_FAULT]`.
2. `saved_flags` маскируется по `INTERLOCK_KNOWN_MASK` (см. `interlocks.h`); если есть «лишние» биты вне маски — данные считаются повреждёнными.
3. При невалидных данных: чистый старт с `SM_IDLE`, `fault_flags=0`, поднимается `ALARM_UNEXPECTED_RESTART` (категория ALARM, value = saved_state как float).

`INTERLOCK_KNOWN_MASK` нужно обновлять при добавлении новых `INTERLOCK_*` бит.

## Phase-4 (H-step-timeout): Таймаут шага AUTO

Подсостояния `AUTO_STARTING_PUMP1`, `AUTO_STARTING_PUMP2`, `AUTO_FILLING_INTERM`, `AUTO_STARTING_PUMP3` ждут внешних событий: подтверждение DI насоса или появление уровня в промбаке. Если событие не приходит из-за неисправности (отказ датчика, обрыв проводки, заклинивший насос, завоздушивание линии), SM раньше зависал в подсостоянии без таймаута — оставались включёнными насосы, не было перехода в FAULT.

Теперь в начале `update_auto` проверяется `elapsed >= step_timeout_s` (значение из `config.timeouts.step_timeout_s`, по умолч. 60 с). При превышении:

- Поднимается `ALARM_STEP_TIMEOUT` (код `0x00B2`, категория ALARM, value = текущий `auto_substate_t`).
- Вызывается `enter_fault(INTERLOCK_STEP_TIMEOUT)` — все выходы выключаются, переход в `SM_FAULT`.

Исключения: `AUTO_RAMP` имеет собственный таймер (`pump_ramp_ms`), `AUTO_RUNNING` — рабочее подсостояние (не транзитное), `AUTO_STOPPING` — мгновенное.

Для подтверждений насосов отдельно работает `check_pump_confirmation` с таймаутом `pump_confirm_ms` (короче — обычно 3 с): он более специфичен и фолтует `ALARM_PUMP{1,2,3}_TIMEOUT`. `step_timeout_s` — общая верхняя граница.

## Phase-3 (L-1): Защита от повреждённого enum

Во всех `switch`-конструкциях SM (`update_auto`, `update_washing`, главный switch по `s_state`) добавлены `default:` ветки. При повреждении памяти (космические лучи, EMI, переполнение стека) переменные enum могут принять невалидное значение — без default-ветки поведение undefined. Теперь:

- `update_auto`: невалидный `auto_sub` → `ESP_LOGE` + `enter_fault(0)`.
- `update_washing`: невалидный `wash_sub` → `ESP_LOGE` + `enter_fault(0)`.
- Главный switch `s_state`: невалидное `state` → safe state (DO=0) + принудительный `s_state = SM_FAULT` + persist в NVS.

## Перечисления (enum)

### sm_state_t -- Основные состояния КА

| Значение | Описание |
|---|---|
| `SM_IDLE` | Ожидание. Все выходы выключены. Принимаются команды `CMD_START_AUTO`, `CMD_START_WASHING`, `CMD_SET_MANUAL`. |
| `SM_AUTO` | Автоматический режим работы. Последовательный пуск насосов, работа установки, автоматический останов при заполнении бака пермеата. |
| `SM_WASHING` | Режим химической промывки мембран горячей водой. Многофазный процесс с подтверждениями оператора. |
| `SM_MANUAL` | Ручной режим. Оператор напрямую управляет дискретными выходами через битовую маску. Блокировки безопасности не действуют (кроме E-STOP). |
| `SM_FAULT` | Аварийное состояние. Все выходы принудительно выключены. Выход только через команду `CMD_RESET_FAULT` при условии, что E-STOP не активен. |

### auto_substate_t -- Подсостояния автоматического режима

| Значение | Описание |
|---|---|
| `AUTO_STARTING_PUMP1` | Пуск насоса подачи (pump_feed, RO1). Ожидание подтверждения от DI6. |
| `AUTO_RAMP` | Разгон устройства плавного пуска (УПП). Ожидание в течение `pump_ramp_ms` (по умолчанию 15000 мс). |
| `AUTO_STARTING_PUMP2` | Пуск насоса 1-й ступени (pump_stage1, RO2). Ожидание подтверждения от DI7. |
| `AUTO_FILLING_INTERM` | Промежуточное состояние: наполнение промежуточного бака. Немедленно переходит к `AUTO_STARTING_PUMP3`. |
| `AUTO_STARTING_PUMP3` | Пуск насоса 2-й ступени (pump_stage2, RO3). Ожидание подтверждения от DI8. |
| `AUTO_RUNNING` | Рабочий режим. Все три насоса работают. При заполнении промбака (DI3) -- отключение 1-й ступени. При заполнении бака пермеата (DI4) -- переход к останову. |
| `AUTO_STOPPING` | Остановка: все выходы выключаются, КА переходит в `SM_IDLE`. |

### wash_substate_t -- Подсостояния режима промывки

| Значение | Описание |
|---|---|
| `WASH_WAIT_HEAT` | Ожидание подтверждения оператора для начала фазы нагрева. Все выходы выключены. |
| `WASH_HEATING` | Нагрев: насос подачи включен, ТЭН управляется гистерезисом. Переход при достижении `target_temp_C`. Таймаут -- `heat_timeout_min`. |
| `WASH_WAIT_SUPPLY` | Ожидание подтверждения оператора для фазы подачи. Насос подачи и ТЭН продолжают работать (поддержание температуры). |
| `WASH_SUPPLY` | Подача горячей воды через мембраны: насос подачи + насос 1-й ступени + ТЭН с гистерезисом. Длительность -- `supply_time_min`. |
| `WASH_WAIT_DRAIN` | Ожидание подтверждения оператора для фазы дренажа. Все выходы выключены. |
| `WASH_DRAIN` | Дренаж: все выходы выключены, ожидание в течение `drain_time_min`. |
| `WASH_DONE` | Промывка завершена: переход в `SM_IDLE`. |

### sm_command_t -- Команды управления КА

| Значение | Описание |
|---|---|
| `CMD_NONE` | Нет команды (значение по умолчанию). |
| `CMD_START_AUTO` | Запуск автоматического режима. Допустима только из `SM_IDLE`. |
| `CMD_STOP` | Остановка. В `SM_AUTO` -- переход к `AUTO_STOPPING`. В `SM_WASHING` -- немедленный переход в `SM_IDLE`. В `SM_MANUAL` -- переход в `SM_IDLE`. |
| `CMD_START_WASHING` | Запуск режима промывки. Допустима только из `SM_IDLE`. |
| `CMD_CONFIRM_WASH_PHASE` | Подтверждение текущей фазы промывки оператором (с HMI). Устанавливает флаг `s_wash_confirm_pending`. |
| `CMD_SET_MANUAL` | Переход в ручной режим. Допустима только из `SM_IDLE`. |
| `CMD_RESET_FAULT` | Сброс аварии. Допустима только из `SM_FAULT` при неактивном E-STOP. |

## Функции

### Публичные функции

#### `void state_machine_init(void)`

**Описание:** Инициализация конечного автомата. Сбрасывает все переменные в начальное состояние, выключает все дискретные выходы.

**Параметры:** Нет.

**Возвращаемое значение:** Нет.

**Алгоритм:**
1. Устанавливает `s_state = SM_IDLE`.
2. Устанавливает `s_auto_sub = AUTO_STARTING_PUMP1`.
3. Устанавливает `s_wash_sub = WASH_WAIT_HEAT`.
4. Сбрасывает `s_fault_flags = 0`.
5. Сбрасывает `s_pending_cmd = CMD_NONE`.
6. Сбрасывает `s_manual_do_mask = 0`.
7. Сбрасывает `s_wash_confirm_pending = false`.
8. Вызывает `all_outputs_off()` -- сброс всех желаемых состояний выходов.
9. Обнуляет массив `s_pump_start_us`.
10. Вызывает `hal_gpio_write_do(0x00)` -- аппаратное выключение всех выходов.
11. Выводит лог об инициализации.

#### `void state_machine_update(void)`

**Описание:** Основная функция обновления КА. Должна вызываться каждые 100 мс из `process_task`. Выполняет проверку блокировок, обработку команд, обновление подсостояний, применение выходов и проверку подтверждений насосов.

**Параметры:** Нет.

**Возвращаемое значение:** Нет.

**Алгоритм:**

1. **Проверка блокировок:** Вызывает `interlocks_check(s_state == SM_MANUAL, &ilk)`. В ручном режиме проверяется только E-STOP.
2. **E-STOP:** Если `ilk.estop_active` и текущее состояние не `SM_FAULT` -- вызывает `enter_fault(INTERLOCK_ESTOP)`.
3. **Чтение команды:** Атомарное чтение `s_pending_cmd` внутри критической секции (спинлок). После чтения команда сбрасывается в `CMD_NONE`.
4. **Обработка по состоянию:**
   - **SM_IDLE:** Все выходы выключены. Обработка команд: `CMD_START_AUTO` -> переход в `SM_AUTO` (подсостояние `AUTO_STARTING_PUMP1`), `CMD_START_WASHING` -> `SM_WASHING` (подсостояние `WASH_WAIT_HEAT`), `CMD_SET_MANUAL` -> `SM_MANUAL`.
   - **SM_AUTO:** При `CMD_STOP` -- переход к `AUTO_STOPPING`. Вызов `update_auto(&ilk)`.
   - **SM_WASHING:** При `CMD_STOP` -- немедленный переход в `SM_IDLE` с выключением выходов. При `CMD_CONFIRM_WASH_PHASE` -- установка `s_wash_confirm_pending = true`. Вызов `update_washing(&ilk)`.
   - **SM_MANUAL:** При `CMD_STOP` -- сброс маски, выключение DO, переход в `SM_IDLE`. Иначе -- проверка зависимостей агрегатов (WARNING-уровень через `alarm_raise`) и запись `s_manual_do_mask` в DO. **Выход из функции через `return`** -- блок применения выходов не выполняется.
   - **SM_FAULT:** Все выходы выключены, DO = 0x00. При `CMD_RESET_FAULT` и неактивном E-STOP -- сброс `s_fault_flags`, переход в `SM_IDLE`. **Выход из функции через `return`**.
5. **Применение выходов (для SM_IDLE, SM_AUTO, SM_WASHING):** Каждый желаемый выход (`s_want_*`) умножается (AND) на разрешение из интерлоков (`ilk.allow_*`). Результат записывается в аппаратные выходы через `hal_gpio_write_do_pin`.
6. **Проверка подтверждения насосов:** Для `SM_AUTO` и `SM_WASHING` вызывается `check_pump_confirmation` для каждого из трёх насосов. При таймауте -- вход в аварию с соответствующим флагом (`INTERLOCK_PUMP1_TIMEOUT`, `INTERLOCK_PUMP2_TIMEOUT`, `INTERLOCK_PUMP3_TIMEOUT`).

**Проверки зависимостей в MANUAL:**
- `pump_stage1` включен без `pump_feed` -> WARNING
- `pump_stage2` включен без `pump_stage1` -> WARNING
- `heater` включен без `pump_feed` -> WARNING

#### `void state_machine_send_command(sm_command_t cmd)`

**Описание:** Отправка команды конечному автомату. Потокобезопасная (используется спинлок). Может вызываться из любой задачи (MQTT, HTTP и т.д.).

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `cmd` | `sm_command_t` | Команда для КА |

**Возвращаемое значение:** Нет.

**Алгоритм:**
1. Вход в критическую секцию (`portENTER_CRITICAL`).
2. Запись команды в `s_pending_cmd`.
3. Выход из критической секции.
4. Лог команды.

**Примечание:** Если до следующего вызова `state_machine_update()` будет отправлено несколько команд, только последняя будет обработана (перезатирание).

#### `void state_machine_manual_set_do(uint8_t mask)`

#### `static bool check_pump_confirmation(uint8_t idx, bool pump_on, uint8_t di_pin)`

**Описание:** Проверка подтверждения работы насоса по дискретному входу с таймаутом.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `idx` | `uint8_t` | Индекс насоса: 0 = pump_feed, 1 = pump_stage1, 2 = pump_stage2 |
| `pump_on` | `bool` | `true` если насос фактически включён (после интерлоков) |
| `di_pin` | `uint8_t` | Номер DI подтверждения (`BOARD_DI_PUMP1_CONF`, `BOARD_DI_PUMP2_CONF`, `BOARD_DI_PUMP3_CONF`) |

**Возвращаемое значение:** `true` -- ОК (насос подтверждён или таймер ещё не истёк), `false` -- таймаут (авария).

**Алгоритм:**
1. Если насос выключен (`pump_on == false`) -- сброс таймера `s_pump_start_us[idx] = 0`, возврат `true`.
2. Если `s_pump_start_us[idx] == 0` (первый цикл после включения) -- запоминает текущее время, возврат `true`.
3. Читает DI и проверяет бит подтверждения. Если подтверждён -- сброс таймера, возврат `true`.
4. Если не подтверждён -- проверяет, не истёк ли таймаут `pump_confirm_ms` (из конфигурации, по умолчанию 3000 мс). Возвращает `true` если ещё не истёк, `false` если истёк.

#### `static void update_auto(const interlock_result_t *ilk)`

**Описание:** Обработка подсостояний автоматического режима.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `ilk` | `const interlock_result_t *` | Результат проверки блокировок (не используется напрямую внутри, но передаётся по контракту) |

**Алгоритм по подсостояниям:**

- **AUTO_STARTING_PUMP1:** Включает `s_want_pump_feed`. Ожидает подтверждение DI6. При подтверждении -> `AUTO_RAMP`.
- **AUTO_RAMP:** Включает `s_want_pump_feed`. Ожидает `pump_ramp_ms`. По истечении -> `AUTO_STARTING_PUMP2`.
- **AUTO_STARTING_PUMP2:** Включает `s_want_pump_feed` + `s_want_pump_stage1`. Ожидает подтверждение DI7. При подтверждении -> `AUTO_FILLING_INTERM`.
- **AUTO_FILLING_INTERM:** Включает `s_want_pump_feed` + `s_want_pump_stage1`. Немедленный переход -> `AUTO_STARTING_PUMP3`.
- **AUTO_STARTING_PUMP3:** Включает все три насоса. Ожидает подтверждение DI8. При подтверждении -> `AUTO_RUNNING`.
- **AUTO_RUNNING:** Все три насоса работают. Логика управления:
  - Если DI4 (бак пермеата полон) -- переход к `AUTO_STOPPING`.
  - Если DI3 (промбак полон) -- отключение `pump_feed` и `pump_stage1`, `pump_stage2` продолжает работу.
  - Если промбак не полон -- все три насоса работают.
- **AUTO_STOPPING:** Вызывает `all_outputs_off()`, обнуляет `s_pump_start_us`, переход в `SM_IDLE`.

---

#### `static bool heater_hysteresis(float t, const config_washing_t *w)`

**Описание:** Реализация гистерезисного управления ТЭНом.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `t` | `float` | Текущая температура в градусах Цельсия |
| `w` | `const config_washing_t *` | Указатель на конфигурацию промывки |

**Возвращаемое значение:** `true` -- нормальная работа, `false` -- перегрев (требуется авария).

**Алгоритм:**
1. Если `t` == NaN (датчик неисправен) -- ТЭН выключается, возврат `true` (не критично).
2. Если `t > max_temp_C` -- возврат `false` (перегрев, авария).
3. Если `t < (target_temp_C - hysteresis_C)` -- ТЭН включается (`s_want_heater = true`).
4. Если `t >= target_temp_C` -- ТЭН выключается (`s_want_heater = false`).
5. В зоне `[target - hysteresis, target)` -- состояние ТЭНа не меняется (гистерезис).

**Пример с параметрами по умолчанию** (target=35, hysteresis=2, max=40):
- T < 33 -> ТЭН ВКЛ
- 33 <= T < 35 -> без изменений (гистерезис)
- T >= 35 -> ТЭН ВЫКЛ
- T > 40 -> АВАРИЯ

---

#### `static void update_washing(const interlock_result_t *ilk)`

**Описание:** Обработка подсостояний режима промывки.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `ilk` | `const interlock_result_t *` | Результат проверки блокировок |

**Алгоритм по подсостояниям:**

- **WASH_WAIT_HEAT:** Все выходы выключены. Ожидание `CMD_CONFIRM_WASH_PHASE` от оператора. При подтверждении -> `WASH_HEATING`.
- **WASH_HEATING:** Насос подачи включен, ТЭН управляется гистерезисом. Проверки: перегрев -> FAULT; таймаут нагрева (`heat_timeout_min`) -> FAULT. При достижении `target_temp_C` -> `WASH_WAIT_SUPPLY`.
- **WASH_WAIT_SUPPLY:** Насос подачи включен, ТЭН с гистерезисом (поддержание температуры). Ожидание подтверждения оператора. При подтверждении -> `WASH_SUPPLY`.
- **WASH_SUPPLY:** Насос подачи + насос 1-й ступени, ТЭН с гистерезисом. Перегрев -> FAULT. По истечении `supply_time_min` -> `WASH_WAIT_DRAIN`.
- **WASH_WAIT_DRAIN:** Все выходы выключены. Ожидание подтверждения оператора. При подтверждении -> `WASH_DRAIN`.
- **WASH_DRAIN:** Все выходы выключены. По истечении `drain_time_min` -> `WASH_DONE`.
- **WASH_DONE:** Все выходы выключены, переход в `SM_IDLE`.
